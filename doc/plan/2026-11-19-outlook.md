- **最初の一歩**: ファームにエンコーダーのカウントを足し、`I` 行の末尾に 2 列増やす（取り決めを 1 行だけ拡げる）。まず静止と手回しでカウントが増えるかを見る。次に `sysid` を左右別々の K・τ で当てる。

### 筋 B: 学習に進む（強化学習・模倣学習）

- **そのまま使えるもの**: `Plant` を gymnasium の環境に包めば、domain randomization（`randomize.sample`）と安全ゲートがそのまま使える。
- **買い足すもの**: なし（CPU で足りる範囲）。LeRobot は 0.6.x で、主に模倣学習と画像（`doc/research/2026-11-19-software.md`）。
- **最初の一歩**: PI を「先生」にして、`Obs` から `Command` を出す小さなネットワークに模倣させる。PI に勝てないのが正しい結果で、そこから「何が足りないか」を考える。
- **やらないほうがよい理由**: 課題がヨー角速度 1 つで、PI がほぼ最適。学習が PI を超える場面が無く、**学習の価値が見えない**。速度とヨーを同時に追う、障害物を避ける、など観測と課題を増やしてからでないと題材が足りない（推測）。

### 筋 C: sim を上げる（MuJoCo の精密化・Isaac Sim）

- **そのまま使えるもの**: `mujoco_plant.py`（実機の代役に既になっている）、同定した数字、ばらつかせ方。
- **買い足すもの**: なし。Isaac Sim は GPU が要り、この PC には無い。クラウド GPU の実費は**調べていない**。
- **最初の一歩**: 実機の同定値を MuJoCo の `diffdrive.xml` に入れ戻し、実機ログと MuJoCo の gz を重ねる。合わない所（滑り・接触）を MuJoCo のパラメーターへ戻すのが、最初の物理エンジン側の R2S になる。

- **買い足すもの**: PC 側の ROS 2 だけなら不要。無線やカメラを足すなら XIAO ESP32S3 Sense。スイッチサイエンスの一つのページで ¥2,629（税込）、在庫 22、注記に「2026 年 1 月現在の在庫は OV3660」。別ページの同じ品は在庫 0 の表示（[検索結果](https://www.switch-science.com/collections/%E3%83%9E%E3%82%A4%E3%82%B3%E3%83%B3%E3%83%9C%E3%83%BC%E3%83%89/products/8969)）。IMU は載っていない【記憶、未確認】。

### 推薦: 筋 A（エンコーダー）を最初に

1. **評価の循環が切れる**。いまの実機の評価は gz だけで、gz のバイアスを同定で引いてから gz で評価する。同定が外れると評価も同じ向きに外れ、気づけない（07 章の自己申告）。エンコーダーなら gz と独立にヨー角速度 `r(ωR−ωL)/b` が出る。**真値の代わり**になる。
2. **左右別の K・τ が測れる**。いまのモデルは左右を同じとみなす（05 章の自己申告）。実機の TT モーターは個体差が大きいはず（推測）。
3. **他の筋の入口になる**。筋 B は題材が増え、筋 C は MuJoCo を直す物差しが増える。

ただし**実機の最初の 1 週間（2 節）が済んでから**。IMU だけの輪を先に 1 周させないと、エンコーダーが何を直したのか分からない。最初の一歩は小さい（`I` 行に 2 列足すだけ）。

## 4. この教材の弱点（学ぶ人の目で）

重い順。

1. **代役が「答え合わせ付きの練習問題」になっている**。loop-demo の代役は sim と同じ式で値だけ違う（`HIDDEN`）。同定すれば必ず近い値が戻る。reality gap の学びは「式が外れる」ところにあるのに、体験できない。01 章の「差」の表 8 行のうち、sim が持つのは 5 つ。遅延・電池・左右差・滑りは表に書いてあるだけ。→ 提案 C。
2. **S2R の幅が当て推量のまま**。`randomize.SPREAD`（K ±20 %、τ ±30 % など）は 06 章が「実機で確かめてはいません」と書く。01 章は「幅は実機で測った範囲から決める」と言うのに、**測った範囲から幅を決める道具がコードに無い**。輪の「R2S → S2R」の矢印が文章だけ。→ 複数ログから幅を出す小さな関数（第 2 巡で提案する）。
3. **一度も実機で回っていない**。教材の数字（τ = 0.2 s、通過率 72 % など）は全部 sim の中の数字。読む人は「sim の中で sim を同定している」と気づく。→ 2 節。
4. **評価に真値が無い**。gz で性能を測り、gz のバイアスを同定で引く。→ 推薦の筋 A。
5. **制御の前提が飛ぶ**。06 章は「PI の零点で極を消し、閉ループを時定数 t_c の一次遅れにします」と書く。伝達関数と極零相殺を知らない人はここで置いていかれる。01 章は一次遅れの式までで、s 領域の説明が無い。→ 06 章の前に半ページの補足、または「式を導かなくても使える」と書く。
6. **入手性が最初の壁**。第一候補の nRF52840 Sense は在庫が細く、次点の MG24 は未コンパイル、nRF54L15 は Arduino から IMU を読めた確認が無い（調査）。「買えない」で止まる人が出る。→ 提案 E。
7. **演習に解答が無い**。1 人で学ぶ教材なので、確かめる手段が無い。数字が動いている間は書けないので締めのあと。

## 6. 筐体設計（CAD）を輪につなぐ

SolidCraft が何かは S021 が調べている。ここでは**道具に依らない受け渡し**だけを決める。どの CAD でも、質量特性の画面の数字と寸法は人が読み取れる。

### 6.1 いまの食い違い（grep と読みで確かめた）

- 寸法が 2 か所にばらばらにある。numpy の `Params` は車輪半径 0.016 m・トレッド 0.08 m、MuJoCo の `diffdrive.xml` は 0.03 m・0.10 m。K も時定数も、片方は直接の数、片方は車体の質量から出る。
- CAD を入れる前に、**寸法の唯一の置き場（寸法表）** が要る。これが CAD と輪の継ぎ目になる。
- sim の IMU は車軸の中心に固定（`SimPlant` の `ay = v·gz`）。MJCF の `imu` サイトも `pos="0 0 0"`。取り付け位置の影響は、MJCF 側でだけ試せる。

### 6.2 CAD から取れる量と入る先

| CAD の量 | 入る先 | 効くところ |
|---|---|---|
| 車輪半径 r、トレッド b | `Params.wheel_radius`・`track`、MJCF の車輪の `size`・`pos` | `ωz = r(ωR−ωL)/b`（01 章）。K_yaw に直接効く |
| 全体の質量、車体の重心位置 | MJCF の `mass`・`pos` | 慣性（下） |
| ヨー慣性 Izz（鉛直軸まわり。質量特性の画面の値と座標系に注意） | 時定数 τ（13 章の式、S020） | τ ≈ (2·Izz·r²/b² + Jw) / c（c = 停動トルク / 無負荷角速度）。MJCF では質量と形から自動で決まる |
| 電池・基板・モーターの質量と位置 | 部品表 → 平行軸の定理で Izz に足す | 置き場所だけで τ が変わる |
| IMU の位置 (x, y, z) と向き | MJCF の `site pos` と `link --axes` | 旋回中の ax・ay（下） |
| モーターの停動トルク・無負荷回転数（CAD ではなく部品表） | MJCF の `gainprm`・`biasprm`、`Params.motor_gain` | K |

### 6.3 最小の題材は 2 つ（手計算の見積もり。実行はしていない）

1. **電池の置き場所 → τ**。MJCF の寸法で手計算すると、Izz ≈ 5.7e-4 kg·m²（箱 0.25 kg と車輪 2 個の平行軸）、式から τ ≈ 0.066 s。08 章の同定値 0.070 s と 6 % の差で、式は大づかみには合う。
   0.1 kg の電池を中心から 4 cm ずらすと、箱だけの見積もりで τ が 0.055 → 0.072 s（+31 %）。**置き場所だけで、現在の `SPREAD`（τ ±30 %）の幅いっぱい動く**。CAD の配置の選択が S2R の幅に直結する、という学びになる。
2. **IMU を旋回中心からずらす → ax**。ずれ d で、その場旋回中に ax = −ω²·d（向心）、ay = α·d（接線）。ω = 3 rad/s・d = 4 cm なら ax ≈ −0.36 m/s²。sim の加速度雑音（0.05 m/s²）より十分大きい。**IMU だけで d を逆算できる**（R2S で CAD の値を直す）。α ≈ ω/τ ≈ 15 rad/s² として ay ≈ 0.6 m/s²。MuJoCo は `site pos` を動かすだけで自動でこれを出す（はず。未確認）ので、sim.py を直さなくてよい。

「CAD を変える → sim で確かめる → 作る → 測って CAD と sim を直す」の 4 歩目は、**質量をはかりで測る**（CAD の密度と造形の充填率で必ずずれる）、**同定で τ を測る**、**旋回中の ax から d を測る**。測った値は寸法表の同じ欄に `source: measured` として上書きし、CAD の値は `source: cad` のまま残す。

## 7. SPREAD を実測から決める道具

- **入力**: 同定の結果 JSON の列（`physlearn sysid log.csv --out run-XX.json` が既に書く形）と、各 JSON に付けた条件の表 `conditions.csv`（`file,battery_v,floor,day,repeat`）。
- **出力**: `spread.json`（`randomize.SPREAD` と同じ 4 つの欄: motor_gain・motor_tau は比、deadband・gyro_bias は足す量）と、条件ごとの中央値の表。
- **最小の実装**（約 40 行、新規 `src/physlearn/spread.py`）: 欄ごとに、中央値からの最大のずれを幅とし、`margin`（既定 1.5）を掛ける。**同じ条件の繰り返しのばらつき（測定の誤差）と、条件を変えたときのばらつき（本当の変化）を分けて**表に出す。繰り返しの幅のほうが大きければ「実験が悪い」と警告し、n < 6 なら「幅が過小かもしれない」と警告する。
  既存への変更は小さい: `randomize.sample`・`evaluate`・`tune` に `spread=SPREAD` の引数、CLI に `eval --spread spread.json`。
- **教材**: 06 章の「t_c の決め方」の前に節を足す（「幅は測って決める」）。実機が無い間は、`sim-log --plant hidden` の隠しパラメータを電池・床の想定で数通りに振った代役で動かして見せる。
- **S020 の物理との突き合わせ**: 3 列の表にする。**物理から**（モーターの定数の公差、電池 4 本の電圧の範囲による K の幅、電池の位置による τ の幅）、**実測から**（上の道具）、**現行の SPREAD**。採用の規則は「安全側に max、ただし差を表に残す」。
  - 実測 ≫ 物理 なら、物理モデルに無い要因がある（摩擦・温度・同定誤差）。
  - 実測 ≪ 物理 なら、条件を振り足りないか、物理の公差が大きすぎる。
  - 電池による K の幅は、アルカリ 4 本の電圧が新品と消耗でおよそ 6.4 → 4.0 V 【記憶、未確認】とすると、K ∝ 電圧 で ±25 % ほどになり、現行の K ±20 % を超える（推測）。
