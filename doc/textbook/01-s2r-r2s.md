# 01. S2R と R2S の考え方

## この章でわかること

- reality gap（sim と実機の差）とは何か。
- S2R（Sim2Real）と R2S（Real2Sim）の意味。domain randomization と system identification。
- その 2 つを「輪」にすると何がうれしいか。
- この教材の車で、何が「差」になるか。
- V-World / R-World と、その境界の API。

## reality gap: sim と実機の差

sim（シミュレーション）は、現実を式で近似したものです。
近似なので、必ずどこかがずれます。このずれを **reality gap** と呼びます。

sim の上でうまく動く制御器を作っても、実機では揺れたり、遅れたり、止まらなかったりします。
原因は、sim が知らない現実の性質です。

## 題材の式

この教材の車を、3 つの式で表します。

### 1. モーター: 一次遅れ

```text
τ·ω̇ + ω = K·u
```

- `u` はモーターへの指令（duty、-1..1）。
- `ω` は車輪の回転の速さ（rad/s）。`ω̇` はその変化の速さ。
- `K` はゲイン。duty 1 を続けたとき、最後に落ち着く速さです。
- `τ`（タウ）は時定数。指令を変えてから、目標までの約 63% に届くまでの時間です。

言葉で言うと「車輪の速さは、`K·u` に向かって、`τ` くらいの時間をかけて近づく」です。
指令を急に変えても、車輪はすぐには追いつきません。

### 2. 差動 2 輪: 前進の速さ

```text
v = r·(ωR + ωL) / 2
```

- `r` は車輪の半径、`ωR`・`ωL` は右と左の車輪の速さ。
- 前進の速さ `v` は、左右の車輪の速さの平均に半径を掛けたものです。

### 3. 差動 2 輪: ヨー角速度

```text
ωz = r·(ωR − ωL) / b
```

- `b` は左右の車輪の間隔（トレッド）。
- 右が左より速いと `ωz > 0`、つまり左に回ります。`Obs` の約束「`gz > 0` が左旋回」と同じ向きです。

言葉で言うと「回る速さは、左右の差で決まる。車輪の間隔が広いほど、同じ差でもゆっくり回る」です。

この教材の課題は、`ωz`（IMU のジャイロなら `gz`）を目標値に合わせることです。

## 何が「差」になるか

| 差の種類 | sim での扱い | 実機で起きること | どう測るか（例） |
|---|---|---|---|
| モーターのゲイン `K` | 1 つの数 | 左右で違う。個体差がある | ステップ応答の落ち着いた値 |
| 時定数 `τ` | 1 つの数 | 負荷や電池で変わる | ステップ応答の立ち上がり |
| デッドバンド | 無いことが多い | 小さな duty では動かない（摩擦に負ける） | duty を少しずつ上げ、動き出す値を見る |
| 電池電圧 | 一定 | 減ると同じ duty でも遅くなる | 満充電と消耗時で同じ試験をする |
| 床の摩擦・滑り | 理想の転がり | 机とカーペットで違う。車輪が滑る | 床を変えて同じ試験をする |
| ジャイロのバイアス | 0 | 静止しても 0 にならない | 静止ログの平均（02 章） |
| ジャイロの雑音 | 無い | 毎回少しずつ違う値 | 静止ログの標準偏差（02 章） |
| 遅延 | 0 | シリアル通信・処理・PWM の分だけ遅れる | 指令を変えた時刻と、`gz` が動き出す時刻の差 |

この表の中身を、sim の側にどう入れるかが 04 章です。

## S2R: sim から実機へ

**S2R（Sim2Real）** は、sim で作った制御器を実機へ持っていくことです。
問題は、sim の数字（`K` や `τ`）が実機と少しずれていることです。

そこで **domain randomization**（ドメインランダム化）を使います。
sim の数字を 1 つに決めず、ありそうな幅でばらつかせます。
たとえば `K` を ±20%、`τ` を ±30%、遅延を 0〜30 ms のように振ります（数字は例です）。
その全部で動く制御器なら、実機がその幅の中にいる限り、たぶん動きます。

ばらつかせすぎると、制御器は慎重になりすぎて遅くなります。
幅は「実機で測った範囲」から決めるのがよいです。これが次の R2S につながります。

06 章で、ばらつきの下でゲインを決めて実機へ持っていきます。

## R2S: 実機から sim へ

**R2S（Real2Sim）** は、実機の測定から sim を直すことです。
中心の道具は **system identification**（システム同定）です。
実機に決まった指令（たとえばステップ: duty を 0 から 0.5 に急に上げる）を入れ、応答を記録します。
その記録に、上の式がいちばん合うような `K`・`τ`・バイアスを探します。

05 章で、ログから同定します（コマンド `physlearn sysid`）。

## 2 つを輪にする

```text
   ┌──────────────── S2R ────────────────┐
   │  sim でゲインを決める                 ▼
 ┌─┴──────────┐                      ┌───────────┐
 │  V-World   │                      │  R-World  │
 │  (sim)     │                      │  (実機)   │
 └─▲──────────┘                      └─────┬─────┘
   │  同定した数字で sim を直す            │ ログを取る
   └──────────────── R2S ◄─────────────────┘
```

1. sim で制御器を作る（最初の sim は、当てずっぽうの数字でよい）。
2. 安全に気をつけて実機で試し、ログを取る（09 章）。
3. ログから同定して sim を直す（R2S）。
4. 直した sim で、ばらつかせて制御器を作り直す（S2R）。
5. 実機で試す。2 に戻る。

1 周ごとに、sim と実機の差が小さくなります。
「差が小さくなった」を数字で言えるようにするのが大事です。
たとえば「同じステップ指令で、sim と実機の `gz` の差の二乗平均」を毎周記録します。
07 章で 1 周を回します（コマンド `physlearn loop-demo`）。

## V-World / R-World と境界の API

この教材では、sim の世界を **V-World**、実機の世界を **R-World** と呼びます。
PoC 設計書から引き継いだ、この教材だけの呼び名です。

大事な決まりは 1 つです。
**制御器から見て、V-World と R-World は同じ形をしている。**
そのための約束が `src/physlearn/api.py` です。

```python
@dataclass(frozen=True)
class Command:
    """左右モーターの指令。-1..1 の PWM デューティ比で、前進が正。"""

    left: float
    right: float


@dataclass(frozen=True)
class Obs:
    """IMU の観測。機体座標は x 前・y 左・z 上（右手系）。"""

    t: float  # 秒。reset からの経過
    ax: float  # 加速度 m/s^2（静止時 az ≈ +9.81）
    ay: float
    az: float
    gx: float  # 角速度 rad/s（gz > 0 が左旋回）
    gy: float
    gz: float


class Plant(Protocol):
    """制御対象。sim も実機もこの 2 つだけを実装する。"""

    def reset(self) -> Obs: ...

    def step(self, cmd: Command, dt: float) -> Obs:
        """cmd を dt 秒かけて、その終わりの観測を返す。"""
        ...
```

- `Command` は「左右の duty」。単位の無い -1..1 の数です。
- `Obs` は「IMU が測ったもの」。単位は m/s^2 と rad/s に揃えます。生の LSB（センサーの数字）は境界の内側で変換します。
- `Plant` は `reset` と `step` だけ。numpy の sim も、MuJoCo も、実機も、これを実装します。
- ログの列も `LOG_COLUMNS`（`Obs` の列 + `left`・`right`）で揃えます。だから sim のログと実機のログを、同じ道具で比べられます。

境界を細く保つと、差し替えが楽になります。
逆に、制御器が「実機のときだけ」の特別扱いを持つと、sim で確かめたことが実機に当てはまらなくなります。

## 演習

1. `τ = 0.1 s`、`K = 20 rad/s` のモーターに、時刻 0 で `u = 0.5` を入れました。十分に時間が経つと `ω` はいくつですか。0.1 秒後はおよそいくつですか。
   - 手がかり: 落ち着く値は `K·u`。0.1 秒は `τ` 1 つ分なので、約 63%。
2. `r = 0.02 m`、`b = 0.1 m`、`ωR = 10`、`ωL = 5`（rad/s）のとき、`v` と `ωz` を求めてください。
   - 手がかり: `v = 0.02·15/2`、`ωz = 0.02·5/0.1`。
3. 上の「差」の表から、domain randomization で振るべきものを 3 つ選び、その幅をどう決めるか書いてください。
   - 手がかり: 幅は当てずっぽうより、実機を何回か測ったばらつきから決めるほうがよい。
