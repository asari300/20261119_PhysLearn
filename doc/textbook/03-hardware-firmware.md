# 3. 実機をつなぐ: 部品・配線・ファームウェア・ログ

この章では IMU（加速度と角速度のセンサー）を内蔵した小さなマイコン基板 Seeed XIAO を PC につなぎ、
(1) IMU の値を PC に流し、(2) PC から 2 つのモーターを回せるようにする。
最後に、次の章の系同定（`physlearn sysid`）で使うログを取る。

> この章の手順は、実機が手元に無い状態で書いた。スケッチは XIAO nRF52840 Sense 向けに
> コンパイルが通ることだけを確かめてある。実機で動かして違いに気づいたら、この章を直してほしい。

部品の価格・買う場所・数は発注リスト `doc/shopping-list.md` を見る（この章には書かない。車体は在庫次第で替わるため）。

（Seeed の wiki の仕様表に IMU が無い）。この教材では使わない。

## 3.2 配線

```
 AE-DRV8835-S を基板の上から見た並び（秋月の取扱説明書の表と基板の写真から。
 実物のシルクとの照合は届いてから【未確認】。10 × 15 mm、2.54 mm ピッチ、6 穴 × 2 列）

           左の列                                  右の列
   電池 (+) 単3×4 ---- VM      o     o  VCC   ---- XIAO 3V3
   左モーター -------- AOUT1   o     o  MODE  ---- GND に直結 (= IN/IN)
   左モーター -------- AOUT2   o     o  AIN1  ---- XIAO D0
   右モーター -------- BOUT1   o     o  AIN2  ---- XIAO D1
   右モーター -------- BOUT2   o     o  BIN1  ---- XIAO D2
   電池 (-) と XIAO GND - GND  o     o  BIN2  ---- XIAO D3
```

| XIAO のピン | つなぐ先 | 定数名（スケッチ冒頭） |
|---|---|---|
| D0 | DRV8835 AIN1 | `PIN_L_IN1` |
| D1 | DRV8835 AIN2 | `PIN_L_IN2` |
| D2 | DRV8835 BIN1 | `PIN_R_IN1` |
| D3 | DRV8835 BIN2 | `PIN_R_IN2` |
| 3V3 | DRV8835 VCC（ロジック電源） | VCC が 0 V だと DRV8835 はスリープして動かない |
| GND | DRV8835 GND・MODE と電池 (-) | （共通の GND にする） |
| — | DRV8835 VM ← 電池 (+) | モーター電源は XIAO から取らない |

- DRV8835 の範囲（TI データシート SLVSB18H の推奨動作条件）: VCC 2〜7 V、VM 0〜11 V、外から入れる PWM 0〜250 kHz。
  XIAO の 3V3 と単3×4（約 6 V）はこの中に入る。
- IN/IN の動き（同 Table 3）: IN1=1・IN2=0 で正転、0・1 で逆転、0・0 で空転（coast）、1・1 でブレーキ。
  MODE が LOW か未接続なら IN/IN（入力は約 100 kΩ で GND に引かれている）。それでも MODE は GND に直結する。
- 電流と保護（TI SLVSB18H。2026-11-19 17:36 JST に https://www.ti.com/lit/ds/symlink/drv8835.pdf の PDF 原本を取得し、本文を読んだ）:
  - 1 つの H ブリッジ（= 1 ch = モーター 1 個）あたり、連続 **1.5 A**（6.1 絶対最大定格 ±1.5 A、6.3 推奨動作条件 IOUT 0〜1.5 A）。ピークは「Internally limited」とあるだけで、値の記載は無い。
  - 2 つのブリッジを並列にすると 3 A（特長欄「Configure Bridges Parallel for 3-A Drive Current」）。この車は 1 ch に 1 個ずつなので並列にしない。
  - 過電流保護（7.3.1.1、6.5）: トリップ電流 IOCP は 1.6〜3.5 A。超えた状態が 1 µs 続くとそのブリッジの FET が全部切れ、約 1 ms 後に自動で戻る。続けば切れては戻るを繰り返す。サーマルシャットダウン（7.3.1.2）: ダイ温度が 150〜180°C（標準 160°C）で切れ、下がれば自動で戻る。どちらも外へ知らせる出力は無い（Table 1「Error report: None」）。
  - つまり 1.5 A 超〜1.6 A 未満は保証も保護も無い隙間にある。連続で 1.5 A を超えさせない。
  - **モーターのストール電流**（車輪を止めたときの電流）は、車体（Robo Base ミニキット 2WD。発注リスト `doc/shopping-list.md`）付属のモーターの値を【未確認】（Cytron のページは 403 で開けず、Web 検索の結果にこのキットの値は無かった。スイッチサイエンスの商品ページは開いていない。車体が元の 2WD からミニに替わる前に調べた記述で、ミニについては何も見つかっていない）。上の 1.5 A に足りているかは、**自分で測って**確かめる:
    1. ドライバーを**通さずに**測る。モーター 1 個の線をドライバーから外し、電池 (+) → テスターの電流レンジ → モーター → 電池 (−) とつなぐ（電池は VM に使うものと同じ。ストール電流は電圧に比例して増えるので、新品で測るのが厳しい側）。
    2. テスターは先にレンジと端子を確かめる（電流の端子とレンジの上限を超えるとヒューズが切れる）。最初は大きいレンジから。
    3. 車輪を指で止め、**1〜2 秒だけ**読んで、すぐ電池を外す。モーターとテスターが熱くなる。もう 1 個も同じに測る。
    4. 1 個でも 1.5 A を超えたら、この構成では使わない（上限 `DUTY_MAX` で守れるとは言えない、下記）。
  - ストール電流が 1.5 A を超えるモーターだった場合: データシートは 1.6〜3.5 A でブリッジが切れる、温度が上がれば切れる、までしか書いていない。**duty の上限 0.6 がどれだけ電流を減らすかは、データシートに記述が無い**【未確認】。PWM の平均の電圧は下がるが、パルスの間の瞬間の電流はモーターの巻線の性質で決まり、ここでは見積もっていない。また XIAO は電流を見ておらず、車輪が引っかかっても止めない（ウォッチドッグは通信が切れたときだけ働く）。
- コンデンサ（TI SLVSB18H 5 ピン表・10.1）: VCC と VM のピンそれぞれに、GND との間に 0.1 µF（以上）の低 ESR のセラミックコンデンサをできるだけ近くに付けるよう勧めている。VM にはさらに「適切なバルクコンデンサ」（電解でよい）を近くに付けるよう勧めているが、容量の指定は無い（9.1 は、必要な量は電源・モーター・ブレーキの方法などで決まる、とだけ書く）。
  - 秋月の AE-DRV8835-S は商品ページと取扱説明書（https://akizukidenshi.com/goodsaffix/AE-DRV8835-S_20210526.pdf 、2026-11-19 17:37 JST 取得）に「電源ライン（VM、VCC）に必要なコンデンサを実装しました」とある。**容量と個数は書かれていない**【未確認】。実装されたものが TI の勧める 0.1 µF のセラミックと VM のバルクの両方を満たすかは分からない。**配線の前に基板を見て**、VM と VCC の近くにコンデンサが載っているかを確かめる。足すかどうかは動かして XIAO のリセットや IMU の乱れがあるかで決める。VM のバルクの容量は出典を見つけていない（調査メモの 100 µF の電解は推測）。
  - モーターの端子に付ける 0.1 µF のセラミック（ブラシの雑音対策）は、Pololu の解説（https://www.pololu.com/docs/0J15/9 、2026-11-19 検索結果の要約で確認、ページ本体は開いていない）に、モーターのケースのそばに 1〜3 個、向きのある電解は避ける（正逆に回すため）、とある。これは TI の勧めではなく、モーターごとに効き方が違うので測って決める。付けなくても動かせる。
- スケッチは **fast decay**（回す向きの入力に PWM、反対側は 0。PWM の休みは空転）にしている。
  duty 0 やウォッチドッグの停止が「両入力 LOW = 空転」になり、急ブレーキがかからないため。
  duty と回転の速さの関係は直線から外れるが、それは次の章の系同定で測る。
- PWM は nRF52 コアの `analogWrite` の既定で 8 bit・約 62.7 kHz（16 MHz / 255。コアのソースで確認）。耳には聞こえない。
- AE-DRV8835-S の 12 ピン（6×2、2.54 mm ピッチ）の並び: 秋月の取扱説明書（https://akizukidenshi.com/goodsaffix/AE-DRV8835-S_20210526.pdf 、上のコンデンサの項と同じ）の表では、ピン番号は「基板左上を起点に反時計回り」で、1 VM・2 AOUT1・3 AOUT2・4 BOUT1・5 BOUT2・6 GND・7 BIN2・8 BIN1・9 AIN2・10 AIN1・11 MODE・12 VCC。基板を上から見ると、**左の列が上から VM・AOUT1・AOUT2・BOUT1・BOUT2・GND、右の列が上から VCC・MODE・AIN1・AIN2・BIN1・BIN2**（説明書の表と基板の写真。S043 の監査 4 巡目が 2026-11-19 17:36 JST に PDF 原本で確かめた。`log/review/2026-11-19-s043-audit4-claude.md`）。上の図はこの並びに合わせてある。**机の上で確かめたのはここまで。実物の基板のシルクと照合したのではない**ので、届いたら、つなぐ前に基板の印字（シルク）が上の並びと同じかを見る【未確認】。違えば、印字のピン名を正とする。
- GND は必ず共通にする。共通でないと信号が伝わらない。
- 前に進めたいのに後ろに回るモーターは、そのモーターの 2 本の線を入れ替える（ソフトで直さない方が分かりやすい）。

## 3.3 書き込み

使うもの: ボード定義「Seeed nRF52 Boards」（非 mbed 版、`Seeeduino:nrf52`）と、ライブラリ「Seeed Arduino LSM6DS3」。

**ボード定義を非 mbed 版にした理由と、まだ分からないこと**:

- Seeed の wiki（https://wiki.seeedstudio.com/XIAO_BLE/ 、2026-11-19 13:54 JST 取得）は、Bluetooth と低消費電力には非 mbed 版、
  「IMU & PDM advanced function」と組み込み機械学習には mbed 版（「Seeed nRF52 mbed-enabled Boards」）を勧めている。
  非 mbed 版で IMU が使えない、という記述は無い。IMU の wiki（https://wiki.seeedstudio.com/XIAO-BLE-Sense-IMU-Usage/ 、同時刻）はボード定義を指定していない。
- ライブラリ 2.0.8 は `TARGET_SEEED_XIAO_NRF52840_SENSE` が定義されていると IMU 用の I2C バス `Wire1` を使い、非 mbed 版のコア 1.1.13 の `variant.h` がこのマクロを定義している（ソース `LSM6DS3.cpp:35-36`・`variant.h:4` で確認）。
  電源ピン `PIN_LSM6DS3TR_C_POWER` もライブラリが HIGH にする（ライブラリのソースで確認）。つまり非 mbed 版でも IMU のバスと電源は正しく選ばれる。
- 非 mbed 版でコンパイルは通る（58,172 バイト、7%）。**IMU が実際に値を返すかは実機で確かめていない**。
- **実機で先に確かめること**: 書き込んだら 3.5 節で `I` の行が流れるかを見る。`# ERR imu not found` が続くなら、mbed 版
  （ボードマネージャの「Seeed nRF52 mbed-enabled Boards」、FQBN は `Seeeduino:mbed:xiaonRF52840Sense`【未確認】）で書き込み直す。
  mbed 版ではこのスケッチをコンパイルしておらず、`analogWrite` の PWM の周波数も上の 62.7 kHz とは違うかもしれない【未確認】。

### Arduino IDE

1. 「ファイル → 基本設定 → 追加のボードマネージャの URL」に
   `https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json` を足す。
2. ボードマネージャで「Seeed nRF52 Boards」を入れる。ボードは「Seeed XIAO nRF52840 Sense」。
3. ライブラリマネージャで「Seeed Arduino LSM6DS3」を入れる。
4. `firmware/xiao_imu_drive/xiao_imu_drive.ino` を開いて書き込む。

### arduino-cli

```sh
arduino-cli config init   # 初めてのときだけ（doc/setup.md の 2.3 節）
arduino-cli config add board_manager.additional_urls \
  https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
arduino-cli core update-index
arduino-cli core install Seeeduino:nrf52
arduino-cli lib install "Seeed Arduino LSM6DS3"
arduino-cli compile --fqbn Seeeduino:nrf52:xiaonRF52840Sense firmware/xiao_imu_drive
arduino-cli upload  --fqbn Seeeduino:nrf52:xiaonRF52840Sense -p /dev/ttyACM0 firmware/xiao_imu_drive
```

- コンパイルの最後に `python` と `adafruit-nrfutil` のコマンドが要る（書き込み用の zip を作るため）。
  無ければ `pipx install adafruit-nrfutil` などで入れ、`python` が `python3` を指すようにする。
- 書き込みに失敗したら、リセットボタンを素早く 2 回押してブートローダーに入れてから、もう一度。

## 3.4 WSL2 で USB シリアルを使う

WSL2 の Linux からは、そのままでは USB 機器が見えない。Windows 側の usbipd-win で渡す。
手順（winget での入れ方、`usbipd list`・`bind` に管理者権限が要ること、WSL のカーネルの条件、
書き込みで USB の ID が変わって `attach` が外れる件）は **`doc/setup.md` の 3 節**にまとめてある。ここには書かない。

WSL 側で `ls /dev/ttyACM*` に出てくれば成功。Windows 側の Arduino IDE で書き込み、WSL ではログ取りだけをする、という分け方でもよい。

## 3.5 端末で動作を確かめる

```sh
uv run python -m serial.tools.miniterm /dev/ttyACM0 115200   # 抜けるのは Ctrl-]（doc/setup.md の 4 節。追加の道具が要らない）
```

1. `I 52310 0.012 -0.034 9.806 0.0011 -0.0007 0.0002` のような行が 1 秒に 100 行流れれば IMU は動いている。
   形の説明は `doc/protocol.md`。

   IMU の測定範囲はスケッチの `setup()` で明示している（数字はライブラリ 2.0.8 の換算式から）:

   | 量 | 範囲 | 1 LSB | 決めた理由 |
   |---|---|---|---|
   | 角速度 | ±1000 deg/s ≈ ±17.5 rad/s | 35 mdps ≈ 6.1×10⁻⁴ rad/s | sim（MuJoCo）で duty 0.5 の旋回が約 9 rad/s（≈ 515 deg/s）。±500 では飽和する。±1000 なら約 1.9 倍の余裕で、既定の ±2000 より 2 倍細かい |
   | 加速度 | ±16 g | 0.488 mg ≈ 4.8×10⁻³ m/s² | ライブラリの既定と同じ。ぶつかったときに飽和しにくい |

   - 実機の旋回の速さは未確認。duty の上限 0.6 で sim の値に比例すれば約 11 rad/s で、まだ範囲内。
   - **飽和は PC からは直接分からない**（知らせる行は無い）。範囲を超えると値は上限に張り付く
     （生の値 32767 × 35 mdps ≈ 1147 deg/s ≈ 20.0 rad/s）。`gz` が ±20.0 付近で平らになっていたら飽和を疑い、duty を下げるか範囲を ±2000 に戻す。
   - IMU の I2C アドレスは 0x6A（スケッチで明示）。ライブラリの既定はクラスで違い、`LSM6DS3` は 0x6A、下位の `LSM6DS3Core` は 0x6B。
     実物の 0x6A は Zephyr の基板定義（`xiao_ble_nrf52840_sense.dts` の `reg = <0x6a>`）と一致する。
     SA0 は GND に固定されている: Seeed の KiCad の基板データ（XIAO nRF52840 V1.1、2025-12 版）で、IMU（U3）のパッド 1（SDO/SA0）のネットは GND。ST のデータシートに「SDO/SA0 を GND につなぐと 1101010b（0x6A）、電源につなぐと 1101011b（0x6B）」とある
     （S043 の監査 4 巡目が 2026-11-19 17:43 JST に取得。`log/review/2026-11-19-s043-audit4-claude.md`）。古い版の基板で違うかは【未確認】。MG24 Sense のアドレスも【未確認】。
     IMU が出ないときは、アドレスを 0x6B に変えて試すのではなく、IMU の電源（P1.08）・`Wire1`・ライブラリを疑う。
2. **車輪を浮かせてから**、`M 0.3 0.3` と打って Enter。両輪が前に回り、約 0.2 秒で止まる（ウォッチドッグ）。
   人の打つ速さでは指令が途絶えるので、止まるのが正しい。
3. `M abc` と打つと `# ERR bad line` が返り、モーターは回らない。
4. 上の 1 を目で見る代わりに（または見たあとに）、合否つきの道具で確かめる: `uv run python -m physlearn.hwcheck stream --port /dev/ttyACM0`（5 秒）。MCU の周期 10±0.5 ms、欠けたサンプル 0、壊れた行 0、`# ERR` 0、加速度のノルム 9.81±0.5 m/s²、ジャイロ平均 ±0.02 rad/s、飽和 0 を `OK`／`NG` で出す。
   偽の XIAO（12 章）に向けて走らせたときは、ジャイロ平均だけが `NG`（偽物のバイアスは 0.08 rad/s）で、ほかは `OK` だった。実機では走らせていない。
   この道具は pyserial でポートを直接開くので、`link` や `fakexiao` が同じポートを開いている間は走らせない。

## 3.6 ログを取る

```sh
# 静止ログ: 机に置いたまま 10 秒（IMU だけでよい）
uv run python -m physlearn.link still --port /dev/ttyACM0 --seconds 10 --out log/still.csv
# 同定用のログ: sim と同じ指令列（physlearn.sim.id_experiment）を同じ安全ゲート越しに流す
uv run python -m physlearn.link id --port /dev/ttyACM0 --out log/id.csv
```

出力は 1 行 = 1 step (10 ms) の CSV で、列は `t,ax,ay,az,gx,gy,gz,left,right`。
使い方（`physlearn sysid log/id.csv`）は 05 章を見る。

指令の並び（旋回成分 u。左 = −u、右 = +u で、u > 0 が左旋回）:
静止 1 秒 → u = +0.2, −0.2, +0.35, −0.35, +0.5, −0.5, +0.35, −0.35 を各 1 秒、それぞれの後に 0 を 1 秒。全体 17 秒（1700 行）。
先頭の静止でバイアスと雑音、振幅の違う段でゲイン・時定数・デッドバンドを見る。
末尾の ±0.35 は最初の ±0.35 と同じ振幅で、前後でゲインが変わったか（電池の低下など）を `sysid` の `drift` で見る（05 章）。

### USB ケーブルのねじれ

ロボットは USB でつないだままその場で回る。一方向に回り続けるとケーブルがねじれて車体を引っぱる。
そこで右と左を同じ大きさ・同じ長さで交互に回し、**正味の回転をほぼ 0** にしている（空転の惰性の差でわずかに残る）。

1 段でどれだけ回るかの見積もり（MuJoCo のモデルで duty 0.5 のとき約 9 rad/s だった値からの換算。実機では未確認）:
u = 0.5 を 1 秒で最大 約 9 rad ≈ 1.4 回転。立ち上がりの遅れとデッドバンドがあるので実際はこれより少ない。
次の段で逆に回して戻るので、ねじれは最大で 1.5 回転ほどと見ておく。

- ケーブルは**上から吊る**（スタンドや棚から垂らし、車体の真上で回るようにする）。床を引きずらない。
- **最初は USB でつなぐ**。ケーブルが硬くてねじれが気になるときに足すのは、極細の USB ケーブルだけ（`doc/research/2026-11-19-wireless.md` の 5 節。外径 2.1 mm、500 mA 定格、抵抗が高く電圧降下が大きいという販売ページの検索抜粋。XIAO がリセットしないかは実機で確かめる【未確認】）。無線化（電池で XIAO を動かす）は、USB で 1 周回してから。
- ログは短く取り、**終わったらすぐ止める**（`SerialPlant` は終了時に停止を送る）。何本も続けて取るときは、間でねじれを手で戻す。

## 3.7 軸の向きを確かめる

この教材の機体座標は **x 前・y 左・z 上**。基板の向きが違えば `--axes` で付け替える。

**基板データからの読み（実物では未確認）**: Seeed の KiCad の基板データ（XIAO nRF52840 V1.1）と ST のデータシートの軸の図を重ねて読むと、IMU（LSM6DS3TR-C、基板上の U3）は部品面（USB-C と同じ面）にあり、基板の中心から USB-C 側へ 1.59 mm、横へ 4.57 mm（USB-C を前に向けたとき機体の左寄り）。基板の外形は 20.955 × 17.78 mm。
軸は、**USB-C を前に向け、部品面を上にして置いたとき**、機体 x = −Y_imu、機体 y = +X_imu、機体 z = +Z_imu。つまり `--axes=-y,x,z`（機体の軸ごとに基板の軸を書く）。
これは図面の矢印の読み取りで、**実物では確かめていない**。ライブラリが軸を入れ替えていないかも実機で確かめる（調査: `doc/research/2026-11-19-dimensions.md` の 2 節。寸法は同 1 節の IMU の行）。

**`--axes` の書き方**: 値が `-` で始まると、argparse が別のオプションと取り違えて `expected one argument` で拒む。**`--axes=-y,x,z` と `=` でつなぐ**（`--axes -y,x,z` は通らない。偽の XIAO と `link still` で確かめた）。`--axes y,-x,z` のように `-` で始まらない値は空白で区切っても通るが、`=` に統一しておくと間違えない。

1. 道具に割り出させる: `uv run python -m physlearn.hwcheck axes --port /dev/ttyACM0`。車体を水平・前を上・左を上、の順に置いて Enter を押すと、加速度が指す軸から `--axes` の文字列を出す。Enter なしで進めたいときは `--no-prompt --settle 5`。右手系にならない（鏡像・同じ軸・傾き）と断られるので、姿勢を取り直す。**出た文字列を以後の `link` コマンドすべてに付ける**。
   - 注意: 道具は `--axes 文字列`（空白区切り）の形で表示する。文字列が `-` で始まるときは、そのまま貼らずに `--axes=文字列` に直す【道具の表示の不具合。直していない】。
   - 偽の XIAO は水平の姿勢しか出せないので、`axes` は 1 姿勢目で止まる（12 章）。実機では走らせていない。
2. 道具が割り出した結果を、手で確かめる（4 つの符号。上の読みと合うかも見る）:
   1. 車体を水平に置いて静止ログを取る。`az ≈ +9.8`、`ax ≈ ay ≈ 0` になるはず。`az ≈ -9.8` なら基板が裏返し。
   2. 車体の前を持ち上げる（鼻上げ）。加速度センサーは重力の反対向き（上向き）を測るので、上を向いた機体 x の成分 `ax` が**正**に動く。
   3. 左側を持ち上げる。同じ理由で `ay` が正に動く。
   4. 上から見て反時計回り（左旋回）に回す。`gz` が**正**になる。
3. 合わなければ `--axes` を直す。例: 基板の y が車の前を向いているなら `--axes y,-x,z`
   （機体 x = 基板 y、機体 y = 基板 -x）。

## 3.8 安全

- 初めて回すときは**車輪を浮かせる**（箱の上に載せる）。
- モーターの電源は電池から DRV8835 の VM へ。XIAO の 3V3 から取らない。理由:
  - DRV8835 はモーター電源 VM（0〜11 V）とロジック電源 VCC（2〜7 V）を別のピンにしている（TI SLVSB18H の特長欄「Separate Motor and Logic-Supply Pins」、6.3）。3V3 は VCC につなぐ側。
  - 3V3 は XIAO の基板上のレギュレーターの出力で、その電流は XIAO 自身と IMU も賄う。Seeed の回路図（XIAO nRF52840 Sense、https://files.seeedstudio.com/wiki/XIAO-BLE/Seeed_Studio_XIAO_nRF52840_PDF.pdf 、2026-11-19 17:37 JST 取得）には、レギュレーター U6「SGM2040-3.3YUDH4G/TR」の脇に「3.3V;250mA」とあり、SG Micro のデータシート（https://www.sg-micro.com/rect/assets/9d7e04e6-7450-4c5c-b94c-fa500b90b628/SGM2040.pdf 、17:38 JST 取得）に Maximum Output Current 250 mA（+25°C）とある。ドライバーの 1 ch の定格 1.5 A（上の「電流と保護」）は、その 6 倍である。
  - ただし、Seeed の回路図の版や製造時期でレギュレーターの型番が違うという指摘が Seeed のフォーラムにある（利用者の投稿。v1.1 の回路図に別の型番を見たという。https://forum.seeedstudio.com/t/xiao-nrf52840-maximum-current-output-of-3-3v-output/288097 ）。手元の基板の型番は【未確認】。Seeed の wiki（https://wiki.seeedstudio.com/XIAO_BLE/ ）には 3V3 ピンから取り出せる電流の上限の記述が無い（「Power Output」とだけ）。上の 250 mA はレギュレーターの能力で、3V3 ピンに出せる保証ではない。
- **単3×4 は DRV8835 の VM だけにつなぐ。XIAO の 5V ピン・BAT・3V3 には直接つながない。** XIAO への給電は USB から。特に 5V ピンは Seeed の KiCad の基板データ（XIAO nRF52840 V1.1）で nRF52840 の VBUS ピンと充電 IC（BQ25101）の入力に**直結**している。nRF52840 の製品仕様（v1.1）の VBUS の絶対最大は −0.3〜+5.8 V で、新品の単3×4（約 6.4 V）はこれを超える。
  出典: `log/review/2026-11-19-s055-audit5-claude.md`（監査 5 巡目。基板データは 18:01 JST に取得して読み、製品仕様は SparkFun に置かれた v1.1 の写しで読んだ。Nordic の公式の最新版は 403 で読めておらず、最新版の値は【未確認】）。実機では何も測っていない。
  電池で XIAO を動かす道（専用の LiPo を BAT パッドに）は、まだこの教材の対象外（`doc/research/2026-11-19-wireless.md` の 4 節と 09 章）。
- duty の上限 `DUTY_MAX`（既定 0.6）はスケッチ冒頭にある。慣れるまで上げない。ミニのトレッドが狭いと、その場旋回がジャイロの範囲（±1000 dps = 17.5 rad/s）を超えるおそれがある（`doc/research/2026-11-19-chassis-alternatives.md` の見積もり。【未確認】）。`DUTY_MAX` の確認はミニのトレッドを測ってからにする。
- PC 側のプログラムが止まれば、200 ms でモーターも止まる。`SerialPlant` は終了時・例外時に停止を送る。
  それでも止まらなければ、電池を外す。

## 3.9 PC から回す: jog と run

偽の XIAO（12 章）で確かめた。実機では確かめていない。どちらも初めは車輪を浮かせる。

- `uv run python -m physlearn.link jog --port /dev/ttyACM0 --right 0.3`: 指定の duty を 0.5 s（上限 1 s）だけ安全ゲート越しに出して止め、後半の gz の平均を出す。右だけ正で gz が正なら向きは合っている。
- `uv run python -m physlearn.link run --port /dev/ttyACM0 --params p.json --out run.csv`: パラメータ JSON からゲインを決め（`randomize.tune`、または `--tc`）、`control.run` と同じ閉ループで +3 → −3 rad/s を 2 s ずつ回す。回の間は 1 s 止める。各回の整定・行き過ぎ・定常偏差と `control.SPEC` の合否を出す。
- 引数の上限: `--target` 5 rad/s、`--seconds` 3 s（jog は 1 s）、jog の duty ±0.6。外れたら回さずに終わる。
- 例外・Ctrl-C では `SerialPlant` が停止を送る。安全ゲートが作動したら（|gz| > 15 rad/s か NaN）、例外で止まり、次の回に進まない。
- ウォッチドッグ（200 ms）を PC から確かめる口は作っていない。3.5 の端末で確かめる。

## 演習

1. 静止ログの `gz` の平均と標準偏差を求めよ。平均は「ゼロ点のずれ（バイアス）」、標準偏差は「ノイズ」である。
   10 秒の静止ログで、`gz` をそのまま積分すると 60 秒後に向きは何度ずれるか。
2. 同定用のログで、u = +0.5 の段が始まってから `gz` がその段の最終値の 63% に達するまでの時間を読み取れ（これが 1 次遅れの時定数の目安）。u = 0.2・0.35・0.5 の段の最終値が u に比例するかを確かめよ（比例しなければデッドバンドを疑う）。
3. 基板を車体に 180° 回して（USB 端子を後ろ向きに）付けたとき、`--axes` に何を指定すべきか答えよ（`-` で始まる値は `--axes=...` と書く）。確かめ方は 2 通り。実機が届いたら、3.7 の手順（`hwcheck axes` と 4 つの符号）でする。それまでは、偽の XIAO（12 章）でする。偽の XIAO は水平の姿勢しか出せず、`hwcheck axes` は 1 姿勢目で止まるので、代わりに、答えと同じ `--axes` で偽の XIAO を立て、`link` の `SerialPlant` を同じ `--axes` でつないで前進の指令を出し、`ax` が正になるか（基準の `-y,x,z` や付け替えなしのままだと、符号が逆か 0 のままか）を見る。
