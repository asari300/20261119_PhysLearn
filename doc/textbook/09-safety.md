# 09. 安全

## この章でわかること

- sim で作った制御器の出力を、実機に流す前に通すべき「ゲート」。
- 実機を動かす前・動かしている間・終わったあとのチェックリスト。
- 電源の分け方と、LiPo 電池の扱いの基本。

小さな車でも、回る車輪・ギヤ・配線・電池には危険があります。
指で挟む、机から落ちる、配線が焼ける、電池が膨らむ、などです。

**sim は安全の仕組みの代わりになりません。**
sim でうまく動いても、現実の摩擦・電池・配線・遅延が同じとは限らないからです（PoC 設計書 7 章から引き継ぎ）。

## ゲート: 制御器と実機の間に置くもの

制御器が出した `Command` を、そのまま実機に送らないでください。
間に、次の関門を置きます。どこに置くか（PC 側か XIAO 側か）は 03 章の実装に従います。
**通信が切れたときに働くもの（ウォッチドッグ）は、必ず XIAO 側に置きます。** PC が止まったら PC 側の仕組みも止まるからです。

いまの実装（03 章のスケッチ `firmware/xiao_imu_drive/xiao_imu_drive.ino`、`src/physlearn/link.py`、`doc/protocol.md`）に入っているのは次のものです。

- XIAO 側の上限: `|duty|` を `DUTY_MAX = 0.6` で切る（PC が 1 を送っても 0.6）。
- XIAO 側の拒否: 数として読めない値（NaN・無限大を含む）の `M` 行は捨てる。
- XIAO 側のウォッチドッグ: 200 ms。起動直後は停止。`SerialPlant` は同じ指令を 50 ms ごとに送り直して、走らせ続ける。
- PC 側: `SerialPlant` が送る前に -1..1 に丸める。終了時・例外時に停止を送る。
- 注意: いまの PC 側の丸めは NaN を拒否せず、-1 にして送ります（XIAO 側で -0.6 に切られて動く）。制御器の出力の NaN は、送る前に自分で 0 にしてください（S010 で確認。コード側へ申し送り）。

変化率の制限・実機の有効化スイッチは、まだ入っていません。表の残りは、自分で足すものです。

| ゲート | 何をするか | なぜ |
|---|---|---|
| 上限（クリップ） | `left`・`right` を、たとえば -0.5..0.5 に切る | 制御器が暴れても速さを抑える。最初は小さく |
| 変化率の制限 | 1 step で変えてよい duty の量を決める | 急な反転でギヤや電源に負担をかけない |
| NaN・範囲外の拒否 | 数でない値や、-1..1 の外の値は 0 にする | 計算の失敗をモーターに流さない |
| ウォッチドッグ | 正しい `M` か `S` が 200 ms 来なければ、XIAO がモーターを止める（スケッチの `WATCHDOG_MS`）。壊れた行では延長しない | ケーブル抜け・PC の停止・プログラムの例外 |
| 終了時の停止 | `SerialPlant` は `with` を抜けるとき・例外のときに必ず `S`（停止）を送る | プログラムが落ちても、ウォッチドッグを待たずに止める |
| 実機の有効化スイッチ | 明示的に「有効」にしない限り動かない。初期値は無効 | sim 用の指令が間違って実機に行かないように |
| 非常停止 | 手で物理的にモーターの電源を切れる | ソフトが全部おかしくなっても止められる |

## チェックリスト

### 動かす前（毎回）

- [ ] 上の表のゲートが全部入っている。
- [ ] 上限は小さい値から始める（たとえば 0.3）。
- [ ] **車輪を浮かせている**（台の上に車体を載せ、車輪が空回りする状態）。最初の試験は必ずこれ。
- [ ] 非常停止（電源スイッチ・電池のコネクタ）に手が届く。
- [ ] ウォッチドッグを試した: 動かしている途中で USB を抜く、またはプログラムを止める。モーターが止まる。
- [ ] 回る部分に、指・髪・ケーブルが近づかない。
- [ ] 机の端から離す。床で走らせるなら、周りに物と人がいない。
- [ ] ログを取る準備ができている（何が起きたかを後で確かめるため）。

### 電源

- [ ] マイコン（XIAO）の電源と、モーターの電源を分けて考えている。モーターは大きな電流を急に流し、電圧を揺らします。マイコンがリセットされる原因になります。
- [ ] GND（0 V の線）は共通にしている（分けるのは電源の線で、基準は揃える。具体的な配線は 03 章）。
- [ ] 電池の極性（+ と −）を、つなぐ前に確かめた。
- [ ] モータードライバーの電流の定格が、モーターの止まったときの電流（ストール電流）に足りている。
- [ ] 動かしたあと、ドライバーとモーターが熱すぎないか触って確かめた（やけどに注意し、まず手を近づけて）。

### LiPo 電池を使うなら

LiPo は軽くて強い電池ですが、扱いを誤ると発火します。一般的な注意です。製品ごとの注意書きに従ってください。

- [ ] 専用の充電器で充電する。充電中は目を離さない。燃えにくい場所（耐火の袋など）で充電する。
- [ ] 膨らんだ・へこんだ・熱い電池は使わない。
- [ ] 使いすぎて電圧を下げすぎない（過放電）。下限の電圧は電池の仕様を確かめる。
- [ ] 端子をショートさせない。金属の上に放置しない。
- [ ] 保管や捨て方は、地域の決まりと製品の説明に従う。

### 実機に新しい制御器を初めて入れるとき

- [ ] sim で、ばらつき（06 章）の全部の場合に発散しなかった。
- [ ] 車輪を浮かせて、指令の向き（前進が正、`gz > 0` が左旋回）が sim と同じだと確かめた。
- [ ] 次に床で、上限を小さくして短い時間（数秒）だけ動かした。
- [ ] 上限を上げるのは、ログを見て問題がないと確かめてから。少しずつ。

### 終わったあと

- [ ] モーターの電源を切る。電池を外す。
- [ ] ログを保存する。気づいたことを書く。

## 演習

1. ウォッチドッグを PC 側だけに置くと、何が起きたときに役に立ちませんか。
   - 手がかり: PC がフリーズした、USB が抜けた。
2. 変化率の制限を 1 step あたり 0.05、step を 20 ms とします。duty が 0 から 0.5 になるまで何秒かかりますか。
   - 手がかり: 0.5 ÷ 0.05 = 10 step。
3. 変化率の制限は、制御器から見ると「モーターの遅れ」が増えたように見えます。sim にもこの制限を入れるべきでしょうか。
   - 手がかり: 01 章の「差」の表。入れないと、それ自体が reality gap になります。
