# 09. 安全

## この章でわかること

- sim で作った制御器の出力を、実機に流す前に通すべき「ゲート」。
- 実機を動かす前・動かしている間・終わったあとのチェックリスト。
- 電源の分け方と、単3電池の扱いの基本。

小さな車でも、回る車輪・ギヤ・配線・電池には危険があります。
指で挟む、机から落ちる、配線が焼ける、電池が熱くなる・液が漏れる、などです。

**sim は安全の仕組みの代わりになりません。**
sim でうまく動いても、現実の摩擦・電池・配線・遅延が同じとは限らないからです（PoC 設計書 7 章から引き継ぎ）。

## ゲート: 制御器と実機の間に置くもの

制御器が出した `Command` を、そのまま実機に送らないでください。
間に、次の関門を置きます。どこに置くか（PC 側か XIAO 側か）は 03 章の実装に従います。
**通信が切れたときに働くもの（ウォッチドッグ）は、必ず XIAO 側に置きます。** PC が止まったら PC 側の仕組みも止まるからです。

いまの実装（03 章のスケッチ `firmware/xiao_imu_drive/xiao_imu_drive.ino`、`src/physlearn/link.py`、`doc/protocol.md`）に入っているのは次のものです。

- XIAO 側の上限: `|duty|` を `DUTY_MAX = 0.6` で切る（PC が 1 を送っても 0.6）。
- XIAO 側の拒否: 数として読めない値（NaN・無限大を含む）の `M` 行は捨てる。
- XIAO 側のウォッチドッグ: 200 ms。起動直後は停止。`SerialPlant` は同じ指令を 50 ms ごとに送り直して、走らせ続ける。
- PC 側の `SafetyGate`（06 章。`control.run()` と `sim-log` は必ず通す）: duty を ±0.6 に切る、変化率を 10 /s に抑える、指令か観測に NaN/inf がある・|gz| > 15 rad/s なら (0, 0) にして以後ずっと止める。
- PC 側の `SerialPlant`（`link.py`）: 有限でない指令（NaN・無限大）は送らずに例外にして停止を送る。|duty| を `link.DUTY_MAX = 0.6` で切る。壊れた行・サンプル以外の行は捨てる。MCU の時刻が戻ったら例外にして止める。終了時・例外時に停止を送る。

実機の有効化スイッチは入っていません。表の残りは、自分で足すものです。

| ゲート | 何をするか | なぜ |
|---|---|---|
| 上限（クリップ） | `left`・`right` を、たとえば -0.5..0.5 に切る | 制御器が暴れても速さを抑える。最初は小さく |
| 変化率の制限 | 1 step で変えてよい duty の量を決める | 急な反転でギヤや電源に負担をかけない |
| NaN・範囲外の拒否 | 数でない値や、-1..1 の外の値は 0 にする | 計算の失敗をモーターに流さない |
| ウォッチドッグ | 正しい `M` か `S` が 200 ms 来なければ、XIAO がモーターを止める（スケッチの `WATCHDOG_MS`）。壊れた行では延長しない | ケーブル抜け・PC の停止・プログラムの例外 |
| 終了時の停止 | `SerialPlant` は `with` を抜けるとき・例外のときに必ず `S`（停止）を送る | プログラムが落ちても、ウォッチドッグを待たずに止める |
| 実機の有効化スイッチ | 明示的に「有効」にしない限り動かない。初期値は無効 | sim 用の指令が間違って実機に行かないように |
| 非常停止 | 手で物理的にモーターの電源を切れる | ソフトが全部おかしくなっても止められる |

## チェックリスト

### 動かす前（毎回）

- [ ] 上の表のゲートが全部入っている。
- [ ] 上限は小さい値から始める（たとえば 0.3）。
- [ ] **車輪を浮かせている**（台の上に車体を載せ、車輪が空回りする状態）。最初の試験は必ずこれ。
- [ ] 非常停止（電源スイッチ・電池のコネクタ）に手が届く。
- [ ] ウォッチドッグを試した: 動かしている途中で USB を抜く、またはプログラムを止める。モーターが止まる。
- [ ] 回る部分に、指・髪・ケーブルが近づかない。
- [ ] 机の端から離す。床で走らせるなら、周りに物と人がいない。
- [ ] ログを取る準備ができている（何が起きたかを後で確かめるため）。

### 電源

- [ ] マイコン（XIAO）の電源と、モーターの電源を分けて考えている。モーターは大きな電流を急に流し、電圧を揺らします。マイコンがリセットされる原因になります。
- [ ] GND（0 V の線）は共通にしている（分けるのは電源の線で、基準は揃える。具体的な配線は 03 章）。
- [ ] 単3×4 は DRV8835 の VM だけにつないでいる。XIAO の 5V ピン・BAT・3V3 には直接つながない（上の「電池（単3×4）の扱い」）。
- [ ] 電池の極性（+ と −）を、つなぐ前に確かめた。
- [ ] モータードライバーの電流の定格が、モーターの止まったときの電流（ストール電流）に足りている。ドライバーの値（1 ch 連続 1.5 A）と、保護が働く電流、モーターのストール電流の測り方は **03 章 3.2 の「電流と保護」**（[03. ハードウェアとファームウェア](03-hardware-firmware.md)）。モーターの値はまだ【未確認】なので、測るまでこの項は埋まらない。
- [ ] ドライバーの VCC と VM の近くにコンデンサが載っているか、配線の前に基板を見た（03 章 3.2 の「コンデンサ」）。
- [ ] 動かしたあと、ドライバーとモーターが熱すぎないか触って確かめた（やけどに注意し、まず手を近づけて）。

### 電池（単3×4）の扱い

**この教材の構成は単3電池 4 本で、LiPo は使いません。** 電池は DRV8835 の VM に直接つなぎ、XIAO の BAT・5V・3V3 にはつなぎません（03 章 3.2）。
**とくに XIAO の 5V ピンに単3×4 を入れてはいけません。** 5V ピンは nRF52840 の VBUS に直結していて（Seeed の KiCad の基板データ）、製品仕様（v1.1）の VBUS の絶対最大は 5.8 V です。新品の単3×4（約 6.4 V）はこれを超えます。出典は `log/review/2026-11-19-s055-audit5-claude.md`（2026-11-19 18:01 JST に取得した基板データと製品仕様の写し。Nordic の最新版は読めておらず【未確認】、実機では測っていません）。XIAO への給電は、最初は USB からです。
注意の出どころは、パナソニックの「電池に関するご注意・ご使用上のお知らせ」（https://panasonic.jp/battery/attention.html 、2026-11-19 17:38 JST 取得）です。使う電池の箱と説明書も読んでください。

- [ ] **向きを確かめる**。+ と − を逆に入れない。4 本全部の向きを見る。パナソニックは「ショート、プラス極・マイナス極の逆接続、加熱、分解、火に入れるなどしないでください」としている。
- [ ] **ショートさせない**。電池の両端、電池ボックスの端子、配線の被覆のはがれが、金属（工具、硬貨、ネジ）に触れないようにする。ばらの電池を金属と一緒に持ち歩かない。ニッケル水素はアルカリより大きな電流が流れうる、と一般に言われるが、その数値の出典は取れていない【未確認】。どちらもショートは禁止（同上）。
- [ ] **新旧・種類を混ぜない**。「新しい電池と使用した電池、他の種類の電池をまぜて使わないでください」（同上）。アルカリとニッケル水素も混ぜない。4 本は同じ銘柄・同じ時期のものにそろえる。
- [ ] **液漏れ**。「液もれしたり、変色、変形、その他今までと異なる時は使用しないでください」「使い切った電池はすぐに機器から取り出してください」「長期間ご使用にならないときは、電池を機器から取り出して保存してください」（同上）。使い終わったら電池を外す（下の「終わったあと」と同じ）。
- [ ] ニッケル水素（充電式）を使うなら、乾電池専用の機器では液漏れにつながるおそれがある、とパナソニックは書いている（この車の電池ボックスが充電式に対応するかは【未確認】）。充電は、電池の説明書が指定する充電器で行う。
- [ ] 変色・変形した電池や、触って熱い電池は使わない。捨て方は地域の決まりと電池の説明に従う。

**LiPo 電池を使う構成に変えるとき**（XIAO の BAT 端子に LiPo をつなぐなど）は、この節の対象外です。XIAO の充電回路・極性・電池の仕様を確かめたうえで、電池の説明書に従ってください。この教材では確かめていません。

### 実機に新しい制御器を初めて入れるとき

- [ ] sim で、ばらつき（06 章）の全部の場合に発散しなかった。
- [ ] 車輪を浮かせて、指令の向き（前進が正、`gz > 0` が左旋回）が sim と同じだと確かめた。
- [ ] 次に床で、上限を小さくして短い時間（数秒）だけ動かした。
- [ ] 上限を上げるのは、ログを見て問題がないと確かめてから。少しずつ。

### 終わったあと

- [ ] モーターの電源を切る。電池を外す。
- [ ] ログを保存する。気づいたことを書く。

## 演習

1. ウォッチドッグを PC 側だけに置くと、何が起きたときに役に立ちませんか。
   - 手がかり: PC がフリーズした、USB が抜けた。
2. 変化率の制限を 1 step あたり 0.05、step を 20 ms とします。duty が 0 から 0.5 になるまで何秒かかりますか。
   - 手がかり: 0.5 ÷ 0.05 = 10 step。
3. 変化率の制限は、制御器から見ると「モーターの遅れ」が増えたように見えます。sim にもこの制限を入れるべきでしょうか。
   - 手がかり: 01 章の「差」の表。入れないと、それ自体が reality gap になります。
