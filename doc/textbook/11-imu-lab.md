# 11 XIAO 単体でやる IMU の実験

> **注意**: この章に載せた出力は、すべて**代役**（実物に見立てた sim）で走らせたものです。
> 実機の XIAO では確かめていません【未確認】。
> 実機の数値は、代役とは違う値になるはずです。

モーターも車体も買わず、XIAO nRF52840 Sense と USB ケーブルだけで進める章です。
対象は車体ではなく、IMU そのものです。
実物の IMU を測って sim の IMU モデルを直し（R2S）、sim で作った処理を実物のデータに掛けます（S2R）。
これで、センサーについての R2S と S2R を 1 周します。
コードは `src/physlearn/imu.py` です。
IMU の基礎（バイアス・雑音・ドリフトとは何か）は [02 章](02-imu.md) にあります。
この章では手を動かします。

## この章でわかること

- 静止した IMU の値が、どれくらいずれていて、どれくらい揺れているか。
- ジャイロを積分した角度が、時間とともにずれていくこと。そのずれが、バイアスを引くとどれだけ減るか。
- ジャイロの尺度と軸の符号を、手で回して確かめる方法。
- 静止ログから sim の IMU モデルを直し、直した sim が実物を再現できたかを確かめる方法。

## 要るもの

- XIAO nRF52840 Sense（03 章のスケッチを書き込んだもの）
- USB ケーブル
- 平らで揺れない机

## 代役の作り方

実機が無いときは、次のコマンドで「実物」の代わりのログを 2 つ作ります。
代役は `SimPlant` です。
IMU のバイアスと雑音は、公称（`Params()`）と違う値にしてあります（`imu.STAND_IN`: `gyro_bias=0.006`、`gyro_noise=0.02`、`accel_noise=0.03`）。

```bash
uv run python -c "from physlearn.imu import stand_in; print(f'旋回の真のヨー角 {stand_in(\"still.csv\", \"turn.csv\"):+.2f} 度')"
```

```
旋回の真のヨー角 +68.75 度
```

- `still.csv`: 30 秒の静止ログ（100 Hz）。
- `turn.csv`: 1 秒止まってから、0.4 秒その場旋回し、2 秒止まるログ。手で回す実験の代わりです。真値は sim の真のヨー角速度を積分した値（+68.75 度）です。

実機では、静止ログを 03 章のコマンドで取ります。

```bash
uv run python -m physlearn.link still --port /dev/ttyACM0 --seconds 30 --out still.csv
```

ログを取る前に、`uv run python -m physlearn.hwcheck stream --port /dev/ttyACM0` で、行が欠けずに来ていること（周期 10 ms、欠け 0、`# ERR` 0）を確かめます（`link` を同じポートで動かしていないときに）。
基板の向きが機体座標（x 前・y 左・z 上）と違うときは、`--axes` で合わせます（03 章）。向きは `uv run python -m physlearn.hwcheck axes --port /dev/ttyACM0` が割り出します。出た文字列が `-` で始まるときは、`--axes=-y,x,z` のように `=` でつなぎます（空白で分けると argparse に拒まれます）。
この章では、基板の部品面を上にして机に置き、z が上を向くようにします。

## 実験 1 静止ログの特性

### やること

XIAO を机に置き、触らずに 30 秒ログを取ります。

### コマンド

```bash
uv run python -m physlearn.imu still still.csv
```

### 代役での出力

```
サンプル 3001 個、30.00 s
サンプル間隔 平均 10.00 ms  揺れ(std) 0.00 ms  最大 10.00 ms
  ax: 平均 -0.00021  標準偏差 0.03023 m/s^2
  ay: 平均 -0.00122  標準偏差 0.02932 m/s^2
  az: 平均 +9.80910  標準偏差 0.02919 m/s^2
  gx: 平均 +0.00036  標準偏差 0.01994 rad/s
  gy: 平均 +0.00017  標準偏差 0.01991 rad/s
  gz: 平均 +0.00570  標準偏差 0.02032 rad/s
加速度のノルム - 9.81 = -0.0008 m/s^2
傾き roll -0.01 度  pitch +0.00 度
gz の積分（ドリフト）: そのまま +9.797 度  バイアスを引いた後 -0.005 度
gz の Allan 偏差（τ s: rad/s）: 0.01: 0.02031  0.1: 0.00664  1: 0.00226
```

### 読み方

- **平均**: 静止しているので、ジャイロの真値は 0 です。平均がそのままバイアスです。代役の gz は +0.00570 rad/s で、仕込んだ 0.006 に近い値が戻りました。
- **標準偏差**: 1 サンプルごとの揺れ（雑音）です。代役の gz は 0.02032 で、仕込んだ 0.02 に近い値です。
- **加速度のノルム - 9.81**: 傾きに関係なく、静止なら 9.81 になるはずです。ずれていれば、加速度計の尺度かバイアスがずれています。
- **傾き**: 重力の向きから出した roll と pitch です。机が水平なら 0 度に近くなります。
- **サンプル間隔**: 代役は sim なので、ちょうど 10 ms で揺れは 0 です。実機の `t` は一定とは限りません。だから積分には `t` の実測の差を使います。
- **Allan 偏差**: τ 秒ずつ平均した値が、隣とどれだけ違うかです。白色雑音だけなら、τ が 10 倍で約 1/√10 ≈ 0.32 倍に減ります。代役では 0.02031 → 0.00664 → 0.00226 と、ほぼその通りに減りました。代役には白色雑音しか入れていないので、当然の結果です。実機では、長い τ で下げ止まったり上がったりするはずです（バイアスのゆらぎ）【未確認】。
- 長い τ は出せません。τ ごとの区切りが 9 個未満になると出力しません。30 秒のログでは τ = 1 s までです。10 s を見たいなら、90 秒以上のログが要ります。

### 実機でやるときの注意

- 机をたたかない。キーボードを打つ振動も入ります。
- USB ケーブルの重みで基板が傾くことがあります。傾きの出力で確かめます。
- 電源を入れた直後は、温度が変わってバイアスも動くことがあります【未確認】。数分待ってから取ると比べやすいです。
- az の平均が -9.81 に近いなら、基板が裏返しか、軸の向きが合っていません（`--axes` を見直す）。

## 実験 2 積分のドリフト

### やること

実験 1 と同じ静止ログで、gz を積分してヨー角を出します。
止まっているので、真値は 0 度です。

### コマンドと代役での出力

実験 1 の出力の、この行です。

```
gz の積分（ドリフト）: そのまま +9.797 度  バイアスを引いた後 -0.005 度
```

### 読み方

- バイアスをそのまま積分すると、30 秒で約 9.8 度ずれました。0.0057 rad/s × 30 s ≈ 0.171 rad ≈ 9.8 度です。止まっているのに、角度は動いたことになります。
- バイアスを引くと -0.005 度まで減りました。
- ただし、これは「同じログで測ったバイアスを、同じログから引いた」結果です。ずれがほぼ 0 になるのは当たり前に近いです。別の時刻に測ったバイアスを使うと、実験 3 のように残ります。
- 「IMU だけでは角度はずれていく」の正体は、このバイアスと、その測り残しです。

### 実機でやるときの注意

- 実機のバイアスは時間や温度でゆっくり動くことがあります【未確認】。ログの前半で測ったバイアスを後半に引いて、どれだけ残るかも見てみてください（演習 1）。

## 実験 3 回転の検算

### やること

1. XIAO を机に置き、1 秒以上触らない（この区間でバイアスを測ります）。
2. 上から見て反時計回り（左回り）に、机の上で 90 度回します。机の角や定規に当てると角度がそろいます。
3. 回したら、また止めておきます。

ログは実験 1 と同じ `link still` で取れます（`--seconds` を 10 程度に）【未確認: 回している間もそのまま記録できるはず】。

### コマンド

```bash
uv run python -m physlearn.imu turn turn.csv
```

### 代役での出力

代役は 90 度ではなく、0.4 秒の旋回です（真値 +68.75 度）。

```
冒頭 1 s のバイアス +0.00355 rad/s
gz の積分 +68.96 度（バイアスを引く前 +69.66 度）。左回し（上から見て反時計回り）で正
90 度回したなら尺度 0.766、1 回転なら 0.192
```

### 読み方

- **符号**: 左回りで正になれば、gz の符号は機体座標（z 上、左旋回で正）と合っています。負なら `--axes` を見直します。
- **尺度**: 本当に 90 度回したなら、`gz の積分 / 90` が 1 に近いはずです。代役は 90 度回していないので、この行は読みません。代役では真値 +68.75 度に対して +68.96 度で、差は 0.21 度でした。
- **冒頭のバイアス**: 1 秒だけで測ったので +0.00355 と、仕込んだ 0.006 からずれています。1 秒の平均は雑音で揺れるからです（0.02 / √100 = 0.002 程度）。それでも回転が短いので、角度への影響は小さく済みました。

### 実機でやるときの注意

- 手で回すと、少し傾いたり、持ち上がったりします。gz 以外の軸にも値が出ます。
- 角度が 90 度から数度ずれるのは、手で合わせた精度の問題かもしれません。1 回転（360 度）にすると、手の誤差の割合が小さくなります。
- 尺度が大きくずれる（0.9 未満や 1.1 超）なら、スケッチの感度の設定（02 章の LSB の換算）を疑います。LSM6DS3TR-C の感度は 02 章でも【要確認】のままです。

## 実験 4 sim の IMU モデルを直す（R2S）

### やること

静止ログから、sim の `Params` の IMU の項を直します。
使う項は 3 つです。

| `Params` の項 | 静止ログから取る値 |
| --- | --- |
| `gyro_bias` | gz の平均 |
| `gyro_noise` | gx・gy・gz の標準偏差の平均 |
| `accel_noise` | ax・ay・az の標準偏差の平均 |

ほかの項（モーターなど）は、`--base` で渡した JSON（無ければ公称）のまま残します。
そのあと、直した sim で同じ長さの静止ログを作り、実物と並べます。

### コマンド

```bash
uv run python -m physlearn.imu r2s still.csv --out imu_params.json
```

### 代役での出力

```
imu_params.json: gyro_bias +0.00570  gyro_noise 0.02006  accel_noise 0.02958
                        実物     直した sim
gz の平均            +0.00570    +0.00540
gz の標準偏差          +0.02032    +0.02039
az の標準偏差          +0.02919    +0.02878
ドリフト 度            +9.79661    +9.28369
引いた後 度            -0.00529    -0.00530
```

### 読み方

- 直した sim は、実物（代役）の標準偏差とドリフトをほぼ再現しました。
- 平均とドリフトが少し違うのは、sim の雑音の乱数が実物と違うからです。30 秒の平均は雑音で 0.02 / √3000 ≈ 0.0004 rad/s ほど揺れます。
- これが「sim が実物を再現できたか」の確認です。並べて大きく違う項があれば、sim のモデルに足りないものがあります。

### sim の IMU モデルに無いもの

今の `SimPlant` の IMU は単純です。実機で次が見えても、この sim では再現できません。

- バイアスは gz にしかありません。gx・gy や加速度のバイアスは入りません。
- az は常に 9.81 で、傾きも尺度のずれもありません。
- 雑音は白色だけです。Allan 偏差の下げ止まり（バイアスのゆらぎ）はありません。
- 3 軸の雑音は同じ大きさです。

実機で gx・gy のバイアスや傾きが大きく出たら、それは「モデルに足りないもの」として記録します。

### 実機でやるときの注意

- 静止ログは、実験 1 と同じ注意で取ります。
- 実機のサンプル間隔が揺れていると、直した sim（間隔は平均で一定）とはドリフトが少し違ってきます【未確認】。

## S2R はどこか

この章の S2R は「sim で作った処理を、実物のデータに掛ける」ことです。

- `imu.py` の統計・積分・バイアス引きは、代役（sim）のログで作り、試験しました（`tests/test_imu.py`）。
- 同じコマンドを、実機で取った CSV にそのまま掛けます。ログの形（`LOG_COLUMNS`）が sim と実機で同じなので、コードは変えません。
- 実機に掛けて結果がおかしいときは、処理ではなく実物の側（向き・傾き・振動）を先に疑えます。sim で処理が正しいことを確かめてあるからです。

## 車体の章とのつながり

- [04 章](04-sim.md)の IMU モデル（`gyro_bias`・`gyro_noise`・`accel_noise`）を、この章で実物の値にします。
- [05 章](05-real2sim.md)の同定は、最初の 1 秒の静止区間でバイアスと雑音を測ります。この章の実験 1 と同じことを、短い区間でやっています。実験 3 で見たとおり、1 秒だけの平均は揺れます。
- [06 章](06-sim2real.md)の制御器は、gz からバイアスを引いて使います（`e = r − (gz − bias)`）。ばらつき評価 (`randomize.py`) は `gyro_bias` を ±0.02 rad/s 振ります。この章で測った実物のバイアスが、その幅に収まっているかを確かめられます。`r2s` が書いた JSON は `Params.load` で読めます。車体を買ったあとは、05 章の同定結果の JSON を `--base` に渡すと、モーターの項を残したまま IMU の項だけ直せます。
- [07 章](07-loop.md)の 1 周で、IMU の項は実験 4 の値から始められます。

## 演習

1. 静止ログを前半と後半に分けます。前半の gz の平均をバイアスとして後半から引くと、後半の積分は何度ずれるでしょう。同じログの平均を引いた実験 2 と比べてください。（ヒント: `imu.yaw_deg(log, bias)` に、切り出した `log` を渡す）
2. 静止ログを 10 秒と 90 秒で取り、Allan 偏差の出る τ の数を比べてください。τ = 10 s が出るには、何秒以上のログが要るでしょう。
3. 実験 3 で、90 度回したログと 360 度回したログを取ります。尺度の値は、どちらが 1 に近くなるでしょう。そうなる理由を、手で合わせる角度の誤差から説明してください。
