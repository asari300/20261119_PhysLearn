# 12. 偽の XIAO で実機の手順を練習する

部品が届く前でも、実機と同じコマンドで「ログを取る → 同定する」の 1 周を通せます。
PC の中に「偽の XIAO」を立て、シリアルの向こう側でスケッチと同じ取り決めを話させます。

## この章でわかること

- 偽の XIAO の仕組みと立て方。
- `python -m physlearn.link` を偽物につないで、静止ログと同定用ログを取る手順。
- 偽物で練習できること・できないこと。

## 仕組み

```
制御器 / sim_log ─ SerialPlant ─ /dev/pts/N ═ pty ═ 偽の XIAO ─ Plant
 (PC 側。実機と同じコード)       (擬似端末)        (fakexiao.py)  (HIDDEN の SimPlant)
```

- pty（擬似端末）は、OS が用意する「線のないシリアル」です。片側を偽物が持ち、もう片側 `/dev/pts/N` を `SerialPlant` が開きます。
- 偽物は `firmware/xiao_imu_drive/xiao_imu_drive.ino` の動きを写しています。起動時は停止。`M <left> <right>` と `S` を受け、`I <t_ms> ax ay az gx gy gz` を 100 Hz で送ります。
- 安全の動きもスケッチと同じ定数です。duty は `DUTY_MAX` = 0.6 で切ります。正しい指令が 200 ms 来ないと止まります。壊れた行・47 文字を超える行は捨てて `# ERR ...` を返し、ウォッチドッグは延ばしません。
- 中で回るのは `HIDDEN`（loop-demo で「実機の代役」にしているパラメータ）の `SimPlant` です。`--plant mujoco` で MuJoCo の機体にもできます（`uv sync --extra mujoco` が要ります）。
- `t_ms` は偽物の中の時刻です。`--speed 2` なら 2 倍速で進みます（試験用）。

## 手順（端末 2 つ）

端末 1 で偽物を立てます。表示された名前が「つなぐ先」です。終わったら Ctrl-C で必ず止めます。

<!-- docs_check: skip 擬似端末が要る。出力は偽の XIAO を立てて手で貼った -->
```
$ uv run python -m physlearn.fakexiao
偽の XIAO: --port /dev/pts/15  (axes=x,y,z speed=1.0 plant=sim)  Ctrl-C で終わる
```

端末 2 で、実機と同じコマンドを打ちます。違うのは `--port` だけです。

<!-- docs_check: skip 擬似端末が要る。出力は偽の XIAO 越しに走らせて手で貼った。bias・noise は実時間のずれで毎回揺れる -->
```
$ uv run python -m physlearn.link still --port /dev/pts/15 --seconds 2 --out still.csv
$ uv run python -m physlearn.link id    --port /dev/pts/15 --out real.csv
$ uv run physlearn sysid real.csv
gyro_bias   0.0772
gyro_noise  0.0155
yaw_gain    8.0027
deadband    0.1500
motor_tau   0.2011
drift       -0.0019
```

- 静止ログ（2 s、200 行）の平均は az = 9.811 m/s²、gz = 0.082 rad/s でした。gz は HIDDEN のジャイロのバイアス 0.08 に当たります。
- 同定用ログは 1700 行（ヘッダーを入れて `wc -l` で 1701）、時刻の刻みは 0.01 s でした。実験は 17 s（静止 1 s のあと、1 s のステップと 1 s の 0 を交互に。振幅は ±0.2・±0.35・±0.5 と、末尾に ±0.35 をもう一度）で、実時間なので約 18 s かかりました（`time` で 17.9 s）。
- 偽物の中の正解（`HIDDEN`）は、ヨーのゲイン 8.0・デッドバンド 0.15・時定数 0.2・バイアス 0.08 です。どれも近い値が戻りました（ゲイン 8.003・デッドバンド 0.150・時定数 0.201・バイアス 0.077）。
- 同じ実験を sim だけで回した `physlearn sim-log --plant hidden` のログからは、ゲイン 8.0063・デッドバンド 0.1500・時定数 0.2011・バイアス 0.0780・`drift` -0.0003 が出ました。シリアルを通しても、同定の結果は sim だけのときとほぼ同じです。バイアスと雑音（と `drift`）は、偽物の実時間のずれで走らせるたびに少し揺れます。
- `drift` は、実験の前半と末尾で同じ振幅（±0.35）のゲインを比べた変化です。偽物のゲインは変わらないので 0 に近い値（-0.0019）です。実機では電池の低下などで 0 から離れるはずです【未確認】。

### PC 側でも duty を切る理由

実験の振幅は最大 0.5 で、XIAO の上限 `DUTY_MAX` = 0.6 より下です。
PC 側の `link.py` も、送る前に同じ `DUTY_MAX` = 0.6 で切り、切った後の値をログに書きます。
もし PC 側とスケッチの上限が食い違うと、ログの指令と実際に回った指令がずれ、同定のゲインとデッドバンドが引っ張られます。
偽物は、こうした「取り決めの食い違い」を部品なしで見つけるための道具です。

## 閉ループも偽物で回す

`python -m physlearn.link` の `jog` と `run`（03 章 3.9）も、`--port` を偽物にすればそのまま回ります。偽物で確かめた出力は 07 章「実機の経路で 1 周」にあります。
`jog --right 0.3` は gz の平均 `+0.578` rad/s、`jog --left 0.3` は `-0.410` rad/s でした（どちらもバイアス 0.08 込み）。左の値は走らせるたびに揺れ、`-0.395`〜`-0.419` を見ました。偽物が実時間で動くためです。
`tests/test_real_loop.py` が、偽物を相手に run → id → 同定 → run を 2 倍速で通します。

`link run` の結果も、実時間の偽物では走らせるたびに少し揺れます。2 回走らせた結果は次のとおりです（整定・行き過ぎ・定常偏差）。

| 走らせ方 | 向き | 1 回目 | 2 回目 |
| --- | --- | --- | --- |
| 公称のゲイン（`tc=0.08`） | +3.0 | 0.76 s、8.9 %、0.001 | 0.75 s、9.4 %、0.001 |
| 同上 | -3.0 | 0.91 s、11.2 %、0.004 | 0.89 s、10.8 %、0.003 |
| `--params fixed.json`（同定後、`tc=0.2`） | +3.0 | 0.52 s、1.2 %、0.002 | 0.56 s、1.0 %、0.001 |
| 同上 | -3.0 | 0.54 s、1.5 %、0.001 | 0.55 s、1.4 %、0.001 |

- 公称のゲインは、整定が 0.6 s を超え、-3.0 は行き過ぎも 10 % を超えるので `仕様 NG` でした（2 回とも）。同定したあとのゲインは 4 つとも `仕様 OK` でした。
- 以前は同定後の +3.0 が整定せず NG のことがありました（原因は【未確認】。実時間の読みの遅れが疑わしい）。今回の 2 回は OK でした。揺れるので、1 回の結果で良し悪しを決めないでください。

## 偽物と本物の違い

偽物が写していないもの:

- USB の遅れと揺れ。偽物は PC の中なので、遅れはほぼ 0 です。本物の遅れは【未確認】。
- IMU の量子化・温度でのバイアスの動き・取り付けの傾き。偽物の雑音は白色雑音だけです。
- 電池の電圧が下がって同じ duty でも遅くなること。
- 機械: 車輪の滑り、ギアのがた、床の凹凸、USB ケーブルの引っ張り。
- スケッチの「IMU が見つからない」ときの `# ERR imu not found`。

診断の道具 `hwcheck`（bringup の段 1・3）を偽物に向けると、次のようになります。

<!-- docs_check: skip 擬似端末が要る -->
```
$ uv run python -m physlearn.hwcheck stream --port /dev/pts/15
サンプル 500 個 / 5.0 秒、`#` 行 0 本、壊れた行 0 本
OK  MCU 周期 平均: 10.00 ms   基準 10±0.5 ms【スケッチ】
...
NG  PC 壁時計 周期 最大: 146 ms   基準 ≤ 50 ms【目安】
...
NG  ジャイロ平均 gx gy gz: -0.0008 -0.0003 +0.0805 rad/s   基準 |平均| ≤ 0.02【SPREAD】
...
```

- `stream` は偽物で通ります。NG は 2 つで、どちらも偽物の性質です。ジャイロ平均は、偽物のバイアスが 0.08 で、基準の ±0.02 より大きく作ってあるため。壁時計の最大は、偽物と道具が同じ PC で動いたための 1 回の遅れで、走らせるたびに違います（62 ms や 146 ms を見ました）。実機の USB の揺れは【未確認】で、50 ms の目安が合うかは実機で見ます。
- `axes` は、偽物が水平の姿勢しか出せないので、3 つの姿勢のどれでも「重力は基板の +z に出た」となり、最後に `NG  2 つ以上の姿勢で重力が基板の同じ軸に出た。…` で断られます（終了コード 1）。Enter を待たずに回すなら `--no-prompt --settle 1`。偽物では `--axes` の文字列を割り出せません。割り出しの動きは、純粋な関数の試験（`tests/test_hwcheck.py`）で確かめてあります。
- `hwcheck` は pyserial でポートを直接開きます。`link` が同じポートを開いている間は走らせないでください（実機でも同じです。`link` を止めてから）。

偽物から本物に替えるとき、変わるのは `--port`（例 `/dev/ttyACM0`）だけです。
コマンド・ログの形・同定の手順はそのまま使えます。基板の向きが違うときだけ、`hwcheck axes` が出した文字列を `--axes` に付けます。先頭が `-` の文字列は、`--axes=-y,x,z` のように `=` でつなぎます（`--axes -y,x,z` と空白で分けると、argparse が別のオプションと読んで拒みます）。

## 演習

1. **軸を当てる**。偽物を `--axes x,z,-y` で立てます（基板を立てて付けた機体のつもり）。`--axes` なしで静止ログを取ると、平均は ay = -9.810、az = 0.001、gy = -0.080 になりました。重力とバイアスがどの軸に出たかから、`link` に渡す `--axes` を当ててください。当たれば az = 9.812、gz = 0.079 に戻ります。先頭が `-` の答えなら `=` でつなぎます。
2. **ウォッチドッグを確かめる**。偽物に Python からつなぎ、`M -0.5 0.5` を 1 回だけ送って、届く行を読み続けます。試したときは、回転の軸の値（`--axes x,z,-y` で立てた偽物だったので gy）が -0.21 から -1.85 rad/s まで大きくなり、そのあと下がり始め、約 0.3 s 後に -0.49 まで戻りました（t_ms の始まりは、偽物を立ててから送るまでの時間で変わります）。送るのをやめてから約 200 ms で止まったことを、自分の出力で確かめてください。
3. **`hwcheck stream` で軸を見る**。偽物を `--axes x,z,-y` で立て、`uv run python -m physlearn.hwcheck stream --port ...` を走らせます。加速度ノルムは OK のままで、ジャイロ平均の NG は gz ではなく gy に出ます（試したときは gy = -0.0795）。`stream` は軸の向きを直さないので、軸を割り出すのは `axes` の仕事だと確かめてください。
4. **壊れた行**。同じつなぎ方で `hello` を送ると、`# ERR bad line` が返ります。`M 1 x` や 50 文字の行でも試し、返事の違い（50 文字の行は別の返事になります）と、どの行がウォッチドッグを延ばさないかを確かめてください。

2 と 4 の最小の例:

```python
import serial
s = serial.Serial("/dev/pts/15", 115200, timeout=0.5)
s.write(b"M -0.5 0.5\n")
for _ in range(50):
    print(s.readline().decode().strip())
```

`uv run python` で動かします（`pyserial` はこのリポジトリの依存に入っています）。
