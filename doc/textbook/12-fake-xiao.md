# 12. 偽の XIAO で実機の手順を練習する

部品が届く前でも、実機と同じコマンドで「ログを取る → 同定する」の 1 周を通せます。
PC の中に「偽の XIAO」を立て、シリアルの向こう側でスケッチと同じ取り決めを話させます。

## この章でわかること

- 偽の XIAO の仕組みと立て方。
- `python -m physlearn.link` を偽物につないで、静止ログと同定用ログを取る手順。
- 偽物で練習できること・できないこと。

## 仕組み

```
制御器 / sim_log ─ SerialPlant ─ /dev/pts/N ═ pty ═ 偽の XIAO ─ Plant
 (PC 側。実機と同じコード)       (擬似端末)        (fakexiao.py)  (HIDDEN の SimPlant)
```

- pty（擬似端末）は、OS が用意する「線のないシリアル」です。片側を偽物が持ち、もう片側 `/dev/pts/N` を `SerialPlant` が開きます。
- 偽物は `firmware/xiao_imu_drive/xiao_imu_drive.ino` の動きを写しています。起動時は停止。`M <left> <right>` と `S` を受け、`I <t_ms> ax ay az gx gy gz` を 100 Hz で送ります。
- 安全の動きもスケッチと同じ定数です。duty は `DUTY_MAX` = 0.6 で切ります。正しい指令が 200 ms 来ないと止まります。壊れた行・47 文字を超える行は捨てて `# ERR ...` を返し、ウォッチドッグは延ばしません。
- 中で回るのは `HIDDEN`（loop-demo で「実機の代役」にしているパラメータ）の `SimPlant` です。`--plant mujoco` で MuJoCo の機体にもできます（`uv sync --extra mujoco` が要ります）。
- `t_ms` は偽物の中の時刻です。`--speed 2` なら 2 倍速で進みます（試験用）。

## 手順（端末 2 つ）

端末 1 で偽物を立てます。表示された名前が「つなぐ先」です。

```
$ uv run python -m physlearn.fakexiao
偽の XIAO: --port /dev/pts/14  (axes=x,y,z speed=1.0 plant=sim)  Ctrl-C で終わる
```

端末 2 で、実機と同じコマンドを打ちます。違うのは `--port` だけです。

```
$ uv run python -m physlearn.link still --port /dev/pts/14 --seconds 2 --out still.csv
$ uv run python -m physlearn.link id    --port /dev/pts/14 --out real.csv
$ uv run physlearn sysid real.csv
gyro_bias   0.0802
gyro_noise  0.0155
yaw_gain    4.9953
deadband    0.1673
motor_tau   0.1958
```

- 静止ログ（2 s、200 行）の平均は az = 9.807 m/s²、gz = 0.0775 rad/s でした。gz は HIDDEN のジャイロのバイアス 0.08 に当たります。
- 同定用ログは 1100 行、時刻の刻みは 0.01 s でした。実時間なので 11 s かかります。
- 偽物の中の正解は、ヨーのゲイン 6.0・デッドバンド 0.2・時定数 0.2・バイアス 0.08 です。バイアスと時定数は戻りました。

### ゲインとデッドバンドがずれた理由（2026-11-19 の main の形で）

この時点の `sim.id_experiment` は旋回の振幅に 0.65 を含みます。PC の安全ゲートの上限は 0.8 なので、ログには 0.65 と書かれます。
しかし XIAO（と偽物）は 0.6 で切ります。ログの指令と、実際に回った指令が食い違います。
そのため同定のゲインが 5.0、デッドバンドが 0.167 に引っ張られました。
同じログから 0.65 の区間より前（900 行）だけを使うと、ゲイン 5.90・デッドバンド 0.200 で、sim だけで回したとき（ゲイン 5.90・デッドバンド 0.200）と同じになりました。
実験の振幅を `DUTY_MAX` 以下にする変更（S008）が入れば、この食い違いは消える見込みです【未確認: S008 の取り込み後に走らせていない】。
偽物は、こうした「取り決めの食い違い」を部品なしで見つけるための道具です。

## 偽物と本物の違い

偽物が写していないもの:

- USB の遅れと揺れ。偽物は PC の中なので、遅れはほぼ 0 です。本物の遅れは【未確認】。
- IMU の量子化・温度でのバイアスの動き・取り付けの傾き。偽物の雑音は白色雑音だけです。
- 電池の電圧が下がって同じ duty でも遅くなること。
- 機械: 車輪の滑り、ギアのがた、床の凹凸、USB ケーブルの引っ張り。
- スケッチの「IMU が見つからない」ときの `# ERR imu not found`。

偽物から本物に替えるとき、変わるのは `--port`（例 `/dev/ttyACM0`）だけです。
コマンド・ログの形・同定の手順はそのまま使えます。

## 演習

1. **軸を当てる**。偽物を `--axes x,z,-y` で立てます（基板を立てて付けた機体のつもり）。`--axes` なしで静止ログを取ると、平均は ay = -9.811、az = 0.006、gy = -0.080 になりました。重力とバイアスがどの軸に出たかから、`link` に渡す `--axes` を当ててください。当たれば az = 9.809、gz = 0.078 に戻ります。
2. **ウォッチドッグを確かめる**。偽物に Python からつなぎ、`M -0.5 0.5` を 1 回だけ送って、届く行を読み続けます。試したときは、t_ms = 970 で gz = 0.17、1160 で 1.23 まで上がりました。そのあと 1170 から下がり始め、1460 で 0.34 でした。送るのをやめてから約 200 ms で止まったことを、自分の出力で確かめてください。
3. **壊れた行**。同じつなぎ方で `hello` を送ると、`# ERR bad line` が返ります。`M 1 x` や 50 文字の行でも試し、どの行がウォッチドッグを延ばさないかを確かめてください。

2 と 3 の最小の例:

```python
import serial
s = serial.Serial("/dev/pts/14", 115200, timeout=0.5)
s.write(b"M -0.5 0.5\n")
for _ in range(50):
    print(s.readline().decode().strip())
```

`uv run python` で動かします（`pyserial` はこのリポジトリの依存に入っています）。
