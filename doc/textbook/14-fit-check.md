# 14. 直した sim を疑う（当てはまりの診断）

## この章でわかること

- 同定した sim が、実機のログをどれだけ再現できているかを数字で見る方法。
- 合わないとき、「ゲインがずれている」のか「時定数がずれている」のか「式の形が違う」のかを分ける方法。
- 同定に使っていないデータで確かめる理由。
- 何回かの同定から、ばらつきの幅（`randomize.SPREAD`）を決め直す方法。

道具は `python -m physlearn.compare` です。サブコマンドは 3 つです。

```bash
python -m physlearn.compare fit LOG.csv PARAMS.json   # ログと同じ指令を sim に流し、gz の残差を見る
python -m physlearn.compare holdout LOG.csv           # 正の向きで同定し、負の向きで確かめる
python -m physlearn.compare spread A.json B.csv ...   # 何回かの同定の幅を SPREAD と並べる
```

## なぜ推定値だけでは足りないか

`physlearn sysid` は、ゲイン・時定数・デッドバンドの「点の値」を返します（05 章）。
これは「一次遅れ + デッドバンド」という式の形を決めたうえで、いちばん合う値です。
式の形が実機と違っていても、sysid は何かしらの値を返します。
値だけを見ても、合っているのかどうかは分かりません。

そこで、同定した sim に**ログと同じ指令**を流し、sim の gz（雑音なし）と実際の gz を引き算します。
この差を「残差」と呼びます。
残差が雑音と同じくらいなら、sim はログを再現できています。
雑音より大きければ、モデルで説明できていない分が残っています。

## 残差の読み方

`fit` は次を出します。

- **雑音**: 最初の静止区間の gz の標準偏差。比べる物差しです。
- **RMSE**: 残差の二乗平均の平方根。全体、立ち上がり（各区間の前 30%）、定常（後ろ 30%）に分けます。
- **モデルで説明できていない分**: √(RMSE² − 雑音²)。
- **残差と指令の相関**: 雑音だけなら 0 に近いはずです。指令と形のそろった残差は、式が足りない合図です。
- **ゲインだけ・時定数だけを何倍にすると、残差の何割を説明できるか**: 残差を「ゲインを少し変えた sim との差」と「時定数を少し変えた sim との差」に当てはめます（線形近似）。
- **判定**: 全体の RMSE が雑音の 2 倍以下なら「雑音の範囲で合っている」。そうでなければ、ゲインと時定数のうち残差をよく説明する方を答えます。どちらでも半分も説明できなければ「式の形が違う」と答えます。

最初は「定常の窓の残差が大きければゲイン、立ち上がりの窓なら時定数」と判定していました。
ところが、時定数を 2 倍にした sim では、1 s の区間の後ろ 30% でもまだ応答が落ち着かず、定常の窓にも大きな残差が出ました（立ち上がり 22.2 倍・定常 13.7 倍）。
そのため窓だけでは分けられず、上の「何倍にすると説明できるか」で判定するように変えました。

同じログに対して 3 つの相手を並べます。ログは次のように作りました。

```bash
physlearn sim-log hidden.csv --plant hidden
physlearn sysid hidden.csv --out hidden_id.json
physlearn sim-log mujoco.csv --plant mujoco
physlearn sysid mujoco.csv --out mujoco_id.json
python -c "from dataclasses import replace; from physlearn.sim import Params; p=Params.load('hidden_id.json'); replace(p, motor_tau=2*p.motor_tau).save('hidden_tau2.json')"
```

| | (a) 同じ式の代役 | (b) MuJoCo の代役 | (c) τ を 2 倍に外した sim |
| --- | --- | --- | --- |
| コマンド | `fit hidden.csv hidden_id.json` | `fit mujoco.csv mujoco_id.json` | `fit hidden.csv hidden_tau2.json` |
| 雑音 | 0.0154 | 0.0051 | 0.0154 |
| RMSE 全体（雑音の何倍） | 0.0238（1.5） | 0.0183（3.6） | 0.3120（20.3） |
| RMSE 立ち上がり | 0.0256（1.7） | 0.0335（6.5） | 0.3413（22.2） |
| RMSE 定常 | 0.0259（1.7） | 0.0051（1.0） | 0.2109（13.7） |
| 残差と指令の相関 / 指令の変化との相関 | +0.52 / −0.14 | +0.13 / −0.56 | +0.76 / −0.00 |
| ゲインだけで説明できる割合 | 49%（1.01 倍） | 6%（1.00 倍） | 14%（1.12 倍） |
| 時定数だけで説明できる割合 | 0%（1.00 倍） | 2%（1.00 倍） | 92%（0.39 倍） |
| 判定 | 雑音の範囲で合っている | ゲインでも時定数でも説明できない → 式の形が違う | 時定数（か遅延）がずれている |

（単位は rad/s。）

- **(a)** 期待どおり、雑音の範囲に入りました。ただし 1.5 倍で、ちょうど 1 ではありません。相関も +0.52 あります。ゲインを 1.01 倍にすると残差の 49% が消えるので、同定したゲインがわずかに小さいのが残っています。原因は sysid の「各段の後ろ 30% を定常とみなす」窓です（05 章の「分かっている偏り」）。τ = 0.2 s では 1 s の段の後ろ 30% でもまだ落ち着いておらず、ゲインが下に出ます。
確かめました: τ・デッドバンドはそのままで、ゲインだけをこのログに最小二乗で当てはめ直すと、K_yaw が 7.860 から 7.977（真は 8.0）になり、全体の RMSE は雑音の 1.55 倍から 1.11 倍に、ゲインで説明できる割合は 49% から 0% に、残差と指令の相関は +0.52 から −0.15 になりました。2 倍のしきい値の内なので「合っている」と判定しました。
- **(c)** 正しく「時定数」と言いました。0.39 倍に戻せ、と出ます（本当は 0.5 倍。線形近似なので外れます）。ゲインを 0.8 倍に外した sim でも試し、「ゲイン（かデッドバンド）」と判定しました（1.27 倍に戻せ、残差の 99% を説明。本当は 1.25 倍）。
- **(b)** 定常は雑音と同じ（1.0 倍）なのに、立ち上がりだけが 6.5 倍です。ゲインや時定数を変えても残差はほとんど消えません。つまり「一次遅れ」という式の形が MuJoCo に合っていません。+0.5 のステップの直後を並べると、最初の 60 ms は実際の gz が sim より 0.08 rad/s 遅れ、そのあと 0.03 rad/s ほど追い越します。一次遅れより「出だしが遅く、あとで速い」形（二次の遅れや、むだ時間に近い形）です。

### 07 章の「同定後に整定が遅くなった」は読み取れたか

07 章では、MuJoCo を代役にすると、同定した後のほうが整定が遅くなりました（0.08 → 0.22 s）。
残差から読み取れたのは手がかりまでです。

- MuJoCo の定常の残差は、指令 0.2 でも 0.5 でも雑音と同じでした。同定したデッドバンド 0 は MuJoCo に合っています。公称のデッドバンド 0.05 で設計した制御器は、要らない 0.05 を足していたことになります。07 章の推測（足していた `sign(r)·d` が無くなった）と矛盾しません。
- 立ち上がりは一次遅れの形をしていません。制御器は「一次遅れの極を PI の零点で消す」設計なので（06 章）、形が違えば消し方がずれます。
- この 2 つのどちらが 0.22 s の主な原因かは【未確認】です。確かめるには、MuJoCo の代役でデッドバンドだけを 0.05 に戻して設計し直し、整定を比べます。

## 取っておいたデータで確かめる

同定に使ったデータで合うのは当たり前に近いことです。
同定に使っていないデータで合って初めて、sim が「使える」と言えます。

同定の実験は左右交互の 6 段です（`sim.id_experiment`）。
`holdout` は、最初の静止と正の向きの 3 段（とその後の 0）で同定し、負の向きの 3 段で確かめます。
左右で特性が違えば、確かめる側だけ合わなくなります。

```bash
python -m physlearn.compare holdout hidden.csv
python -m physlearn.compare holdout mujoco.csv
```

| | 同定に使った（正の向き） | 使っていない（負の向き） |
| --- | --- | --- |
| hidden の RMSE 全体（雑音の何倍） | 0.0230（1.5） | 0.0210（1.4） |
| mujoco の RMSE 全体（雑音の何倍） | 0.0177（3.4） | 0.0176（3.4） |

どちらの代役も左右対称なので、使っていない側でも同じくらい合いました。
これは「この道具で左右差が見える」ことの確認にはなっていません。左右差のある代役での確認は【未確認】です（15 章の代役で試す予定）。
MuJoCo では、使った側でも使っていない側でも 3.4 倍です。式の形の違いは、データを分けても消えません。

## 何回かの同定から幅を決める（S2R へ戻す）

06 章の `SPREAD` は「ゲイン ±20%、時定数 ±30%、デッドバンド ±0.03、バイアス ±0.02」です。
この幅は当て推量でした。
実機なら、電池の残量や床を変えて何回か同定すれば、本当の幅が分かります。

実機の代わりに、隠しパラメータ `HIDDEN` を少しずつ変えた 4 台を作りました（ゲイン ×0.9〜1.1、時定数 ×0.9〜1.15、デッドバンド −0.02〜+0.02）。

```bash
python -c "
from dataclasses import replace; from physlearn import HIDDEN
for i,(g,t,d) in enumerate([(1.0,1.0,0.0),(0.9,1.1,0.02),(1.1,0.9,-0.02),(0.95,1.15,0.01)]):
    replace(HIDDEN, motor_gain=HIDDEN.motor_gain*g, motor_tau=HIDDEN.motor_tau*t, deadband=HIDDEN.deadband+d).save(f'v{i}.json')"
for i in 0 1 2 3; do physlearn sim-log v$i.csv --params v$i.json --seed $i; done
python -m physlearn.compare spread v0.csv v1.csv v2.csv v3.csv
```

`spread` は CSV なら同定してから、JSON ならそのまま読みます。

| キー | 平均 | 実測の半幅 | SPREAD | 比 |
| --- | --- | --- | --- | --- |
| motor_gain（比） | 19.3477 | 0.1080 | 0.200 | 54% |
| motor_tau（比） | 0.2032 | 0.1112 | 0.300 | 37% |
| deadband（足す量） | 0.1526 | 0.0201 | 0.030 | 67% |
| gyro_bias（足す量） | 0.0784 | 0.0036 | 0.020 | 18% |

どれも SPREAD の内でした。
作った幅（ゲイン ±10%、時定数 −10〜+15%、デッドバンド ±0.02）は、ほぼそのまま戻ってきています。
バイアスは変えていないので、残った 0.0036 は同定のばらつきです。
道具は、実測の半幅の 1.5 倍を候補として出します（回数が少ないと幅を小さく見積もるため）。
この例では `{'motor_gain': 0.162, 'motor_tau': 0.167, 'deadband': 0.03, 'gyro_bias': 0.005}` です。
`SPREAD` 自体は書き換えません。実機で何回か測ってから決めます。

注意: 幅を狭めると `randomize.evaluate` の通過率は上がります。それは「楽な試験にした」だけかもしれません。測っていない条件（別の床、満充電と空の電池）が入っているかを確かめてから狭めます。

## 実機のログでやるときの手順

1. 実機で同定の実験をしてログを取る（03 章）: `uv run python -m physlearn.link id --port /dev/ttyACM0 --out id.csv`
2. 同定する: `physlearn sysid id.csv --out real.json`
3. 当てはまりを見る: `python -m physlearn.compare fit id.csv real.json`
4. 左右差を見る: `python -m physlearn.compare holdout id.csv`
5. 電池や床を変えて 1〜2 を何回か繰り返し、幅を見る: `python -m physlearn.compare spread real1.json real2.json ...`
6. 図で見る: `python -m physlearn.plot log id.csv --out fit.png --params real.json`

ポート名は環境で変わります（03 章）。実機での確認は、まだしていません【未確認】。
