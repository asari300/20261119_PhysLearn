# 15. パラメータを合わせても残る差

## この章でわかること

- これまでの「実機の代役」`HIDDEN` は、sim と同じ式で値だけが違いました。だから同定すれば必ず合いました。
- 実機には、sim の式に無い現象があります。この章では、それを 1 つずつ足した代役 `HardPlant` を使います。
- 現象ごとに、同定の結果と残差（14 章の診断）にどんな症状が出るかを見ます。
- 全部入りの代役で R2S → S2R を 1 周回し、同定してもなお仕様を外すことを見ます。

```bash
uv run python -m physlearn.mismatch one    # 現象を 1 つずつ入れて同定・診断
uv run python -m physlearn.mismatch loop   # HIDDEN と全部入りで 1 周ずつ
```

コードは `src/physlearn/mismatch.py` です。

## 01 章の「差」の表のうち、sim が持っていなかったもの

01 章の表は 8 行あります。`SimPlant` が式として持つのは、ゲイン K・時定数 τ・デッドバンド・ジャイロのバイアス・ジャイロの雑音の 5 つです。
持っていないのは、次の 3 つです。

- 左右で違うゲイン（表では「K: 左右で違う」）
- 電池電圧の低下
- 遅延

床の摩擦・滑りも持っていません。この章でも扱いません。
加えて、表に無い「IMU の取り付け位置」も足しました（S012 のレビューの指摘 7）。

## 代役 `HardPlant`

`SimPlant` を継いで、指令と観測の間に現象を足します。
引数を 0 にすると、その現象は切れます。全部 0 なら `SimPlant` と同じ結果です（試験で確かめています）。

| 引数 | 現象 | 既定値 | 出どころ |
|---|---|---|---|
| `delay` | 指令が効き始めるまでのむだ時間 | 0.04 s | 仮の値（USB・マイコンの周期・ドライバーで 30〜50 ms と見積もった真ん中） |
| `lr` | 右のゲイン ×(1+lr)、左 ×(1−lr) | 0.10 | 仮の値 |
| `fb` | 左モーターだけ、前に回すときのゲイン ×(1+fb) | 0.10 | 仮の値 |
| `sag` | 電池の低下。ゲインが最大で ×(1−sag) まで落ちる | 0.27 | 13 章（アルカリの新品から消耗で K が −27%）。ただし 13 秒で使い切る速さは仮 |
| `imu_x` | IMU が旋回中心より前に d ずれている | 0.03 m | 仮の値 |

ゲインの差は、duty を「デッドバンドの外側だけ g 倍」に直してから sim に渡して作っています。
こうすると車輪の速さがちょうど g 倍になります。

## 現象を 1 つずつ

`python -m physlearn.mismatch one` の出力です。
代役の元の値は `HIDDEN` で、yaw_gain = 7.860、motor_tau = 0.196、deadband = 0.150 が「合っているとき」の同定値です（`lr` と `imu_x` の行がそれです）。
「定常の差」は実 − sim を gz の向きのまま並べています。ステップの順は +0.2、−0.2、+0.35、−0.35、+0.5、−0.5 です。

### 遅延

式: 時刻 t の指令が、t + 0.04 s に効きます。

```
--- delay=0.04
  同定: yaw_gain=7.828  motor_tau=0.236  deadband=0.150
  残差 RMS 全体 0.085 立ち上がり 0.142 定常 0.046（雑音 0.015） 負の向きで確かめると 0.084
  定常の差（実 - sim、ステップ順）: +0.01 -0.01 +0.05 -0.05 +0.09 -0.09
  判定: ゲインでも時定数でも説明できない → 式の形が違う（遅延・左右差・非線形など）
```

読み方:

- τ が 0.196 から 0.236 に増えました。sysid には遅延の項が無いので、遅れを時定数に押し込みます。
- 残差は立ち上がりで大きく（0.142）、雑音 0.015 の 9 倍あります。
- 「定常の差」も向きと同じ符号で出ています。後ろ 30% の窓でも、遅れた分がまだ残っているからです。
- 14 章の判定は「式の形が違う」でした。ゲインでも時定数でも直らない、と正しく言えています。

### 左右のゲイン差（lr）: 思ったとおりにならなかった

最初は「右回りと左回りで定常値が分かれる」と考えていました。分かれませんでした。

```
--- lr=0.1
  同定: yaw_gain=7.860  motor_tau=0.196  deadband=0.150
  残差 RMS 全体 0.024 立ち上がり 0.026 定常 0.026（雑音 0.015） 負の向きで確かめると 0.021
  判定: 雑音の範囲で合っている
  ax の平均（動いている間）-0.001 m/s^2   前後の道のり 0.038 m
```

理由は式で分かります。その場旋回のヨー角速度は r(ω_R − ω_L)/track です。
左が −0.9a、右が +1.1a なら、差は 2a で、左右が同じときと変わりません。
向きを逆にしても同じです。だから gz には何も出ません。同定値も `HIDDEN` と同じでした。

代わりに出るのは前後の動きです。前後の速さは r(ω_R + ω_L)/2 = 0.1·r·a で、0 になりません。
13 秒の実験で、前後に 0.038 m 動きました（道のりで数えています。向きを交互にしているので戻ってきます）。
gz だけを見る同定と制御では、この差は見えません。

### 回る向きでゲインが違うモーター（fb）

向きで定常値が分かれるのは、モーター自身が「前に回すときと後ろに回すとき」で違う場合でした。
左モーターだけ前転を 10% 強くしました。左が前に回るのは負の向きの旋回です。

```
--- fb=0.1
  同定: yaw_gain=8.056  motor_tau=0.196  deadband=0.150
  残差 RMS 全体 0.036 立ち上がり 0.035 定常 0.040（雑音 0.015） 負の向きで確かめると 0.070
  定常の差（実 - sim、ステップ順）: -0.00 -0.01 -0.01 -0.06 -0.02 -0.11
  判定: ゲインでも時定数でも説明できない → 式の形が違う（遅延・左右差・非線形など）
```

読み方:

- sysid は 1 つの K（8.056）にならしました。正の向きの 7.86 と、負の向きの約 8.25 の間です（負の向きの値は 7.86 × 1.05 から計算した見込みで、出力した値ではありません）。
- 「定常の差」は、負の向きのステップ（2・4・6 番目）だけが大きく負です。負の向きは実機のほうが速く回る、ということです。
- 正の向きで同定して負の向きで確かめると、残差が 0.036 から 0.070 にほぼ倍になります（14 章の `holdout`）。

### 電池の低下（sag）: 思ったとおりにならなかった

式: ゲインに g = 1 − 0.27 · min(1, 経過時間 / 13 s) をかけます。`reset` しても電池は戻りません。

```
--- sag=0.27
  同定: yaw_gain=5.901  motor_tau=0.193  deadband=0.131
  残差 RMS 全体 0.044 立ち上がり 0.040 定常 0.049（雑音 0.015） 負の向きで確かめると 0.046
  定常の差（実 - sim、ステップ順）: -0.02 +0.04 +0.12 -0.05 +0.06 +0.06
  判定: ゲインでも時定数でも説明できない → 式の形が違う（遅延・左右差・非線形など）
```

「前半は実機が速く、後半は遅い」と、時間とともに残差が流れる形を期待していました。そうきれいには出ませんでした。
向きをそろえる（負のステップの符号を反転する）と −0.02、−0.04、+0.12、+0.05、+0.06、−0.06 です。

理由は実験の組み方にあります。`id_experiment` は指令を 0.2 → 0.35 → 0.5 と、時間とともに大きくします。
だから「時間が経った」と「指令が大きい」が重なります。
sysid が定常値に引く直線 y = K(u − db) は、傾き K を小さく（5.901）、デッドバンドを小さく（0.131）して、電池の低下をほとんど飲み込みました。
時間の流れと指令の大きさを分けたいなら、同じ大きさのステップを最初と最後に入れる実験が要ります【未確認: 試していない】。

### IMU の位置ずれ（imu_x）

式: IMU が旋回中心から前に d ずれていると、
ax に −ω²d（向心）が、ay に α·d（α は角加速度）が乗ります。gz は剛体のどこで測っても同じです。

```
--- imu_x=0.03
  同定: yaw_gain=7.860  motor_tau=0.196  deadband=0.150
  判定: 雑音の範囲で合っている
  ax の平均（動いている間）-0.075 m/s^2   前後の道のり 0.000 m
```

読み方:

- 同定値も残差も、ずれの無いとき（`lr` の行と同じ値）と全く同じです。gz を使う同定と制御には影響しません。影響しないことを確かめるのも成果です。
- ax には、動いている間の平均で −0.075 m/s² が出ました。止まっているはずの前後方向に、加速度があるように見えます。
- 11 章の傾きの推定のように加速度を使う処理だけが、これを誤差として受け取ります。旋回中に ax から傾きを出すと、前に傾いたように見えるはずです【未確認: 11 章の推定には通していない】。
- 16 章（筐体設計）では、同じ現象を MuJoCo で見せる予定です。式は同じ ax = −ω²d です。

## 全部入りの 1 周（山場）

`python -m physlearn.mismatch loop` の出力です。
流れは `loop_demo` と同じです: 公称の sim でゲインを決める → 代役で試す → 代役のログで同定 → 決め直す → 代役で試す。

```
=== HIDDEN（同じ式）
  前 (公称) tc=0.08: 整定 0.64 s 行き過ぎ 6% 定常偏差 0.081 NG
  同定: K=7.87 tau=0.196 db=0.150
  後 (同定) tc=0.2 sim 通過率 70%: 整定 0.50 s 行き過ぎ 0% 定常偏差 0.001 OK
=== HardPlant（全部入り）
  前 (公称) tc=0.08: 整定 0.90 s 行き過ぎ 13% 定常偏差 0.087 NG
  同定: K=5.75 tau=0.236 db=0.132
  後 (同定) tc=0.2 sim 通過率 10%: 整定 inf s 行き過ぎ 0% 定常偏差 0.373 NG
    電池そのまま tc=0.2: 整定 inf s 行き過ぎ 0% 定常偏差 0.373 NG
    電池そのまま tc=0.3: 整定 inf s 行き過ぎ 0% 定常偏差 0.373 NG
    電池そのまま tc=0.4: 整定 inf s 行き過ぎ 0% 定常偏差 0.373 NG
    電池を新品に tc=0.2: 整定 0.93 s 行き過ぎ 12% 定常偏差 0.001 NG
    電池を新品に tc=0.3: 整定 0.49 s 行き過ぎ 0% 定常偏差 0.017 OK
    電池を新品に tc=0.4: 整定 0.86 s 行き過ぎ 0% 定常偏差 0.031 NG
```

（`loop` の出力から、HIDDEN の「tc を変えて試す」6 行を省きました。HIDDEN には電池が無いので、「電池を新品に」の行も前と同じ値です。）

読み方:

- 同じ式の `HIDDEN` は、同定すれば仕様を満たしました。これまでの章の話です。
- 全部入りは、同定しても仕様を外しました。定常偏差 0.373 rad/s が tc を変えても全く変わりません。
- これは制御器のせいではありません。同定の実験で電池を使い切り、3 rad/s に要る duty が安全ゲートの上限 0.6 を超えています（計算: 消耗後の K は 7.86 × 0.73 ≈ 5.74、要る duty は 3 / 5.74 + 0.15 ≈ 0.67）。どの制御器でも出せない速さです。
  「パラメータを合わせる」より先に、「その仕様がいまの実機で出せるか」を確かめる必要があります。
- 電池を新品に替えると、同定した sim（電池が減っていく途中の K = 5.75 を見た）より実機が速くなります。遅延も加わって、tc = 0.2 では行き過ぎが 12% 出て NG でした。
- tc を 0.3 に緩めると仕様を満たしました（整定 0.49 s、行き過ぎ 0%）。制御器に余裕を持たせる手が効いた例です。0.4 まで緩めると、今度は遅すぎて整定時間（0.86 s）が仕様の 0.6 s を超えました。

## 実機でこれを見分けるには

14 章の `python -m physlearn.compare` を使います。

- `fit` の判定が「式の形が違う」なら、パラメータでは直らない差があります。この章では遅延・向きの差・電池でそう出ました。
- 立ち上がりの残差が定常より大きければ、遅延を疑います。指令を変えた時刻と gz が動き出す時刻の差を、ログで直接測ります（01 章の表の「どう測るか」）。
- `holdout`（正の向きで同定、負の向きで確かめる）で残差が増えれば、向きで違うモーターを疑います。
- 電池は、同じ実験を満充電と消耗のときに 1 回ずつして、同定値を比べます（`compare spread`）。
- 左右のゲイン差と IMU の位置ずれは gz に出ません。前後の動き（目で見る、または ax）で確かめます。

## モデルに項を足すか、ばらつきで覆うか、制御で吸収するか

- **モデルに項を足す**: 遅延のように、測れて、毎回同じ量なら、sim と sysid に項を足すのが筋です。τ に押し込まれなくなります。
- **ばらつきで覆う**: 電池のように、使うたびに動くものは、1 つの値に決められません。13 章の幅（−27%〜+7%）を `randomize.SPREAD` に入れて、どの値でも仕様を満たす制御器を探します。
- **制御で吸収する**: 小さな遅延や向きの差は、tc を緩めて余裕を持たせると吸収できました（この章では 0.2 → 0.3）。代わりに応答は遅くなります。
- どれでも直らないものもあります。出せない速さ（飽和）は、仕様か機体（電池・モーター）のほうを変えます。

## 演習

1. `HardPlant(delay=...)` の遅延を 0.01・0.04・0.08 s にして `one` と同じ同定をし、同定の τ が遅延とともにどう増えるかを表にしてください。τ の増え方は、遅延の何倍くらいでしょうか。
2. `id_experiment` を真似て、0.35 のステップを最初と最後に入れた指令列を作り、`sag` を入れた代役で前半と後半の定常値を比べてください。電池の低下が時間の流れとして見えるでしょうか。
3. 全部入りの代役で、`tc = 0.3` が仕様を満たしたのは電池を新品に替えたときだけでした。`sag` の幅を `randomize.SPREAD["motor_gain"]` に反映するなら、どの値にするべきか、13 章の表から考えてください。
