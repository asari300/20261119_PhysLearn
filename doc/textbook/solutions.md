# 演習の解答集

各章の末尾の演習の解答です。手を動かす問は、2026-11-19 夕方の main のコード（車輪半径 0.030 m・トレッド 0.100 m・`motor_gain` 20、同定の実験 17 s）で実際に走らせ、その出力の数値を書いています。実機は使っていません。実機が要る問は、偽の XIAO（12 章）か代役（`physlearn sim-log --plant hidden`、`imu.stand_in`）で解き、そのことを書いています。

- 乱数の種や代役の値が変われば、細かい数値も変わります。桁と傾向を見てください。
- 試しのスクリプトは載せず、要点の数行だけを書きます。
- 走らせていないものは【未確認】と書きます。

## 00 章 全体像

**1. 画面で作って実物で動かすもの**
答え（例）: ドローンの飛行制御。差は、重さ（電池を替えると変わる）、プロペラの曲がり、風、電池の電圧が下がること、センサーの雑音と遅れから生まれます。

**2. 制御器が相手を知らなくてよいのはなぜ**
答え: 制御器は `Command` を出して `Obs` を受け取るだけで、相手が `Plant` の約束（`reset()` と `step(cmd, dt)`）を守っていれば中身を見ないからです。`src/physlearn/api.py` の型と、`sim.SimPlant`・`mujoco_plant` がどちらも同じ形を実装していることで確かめられます。

**3. エンコーダーを使わないと何が測れないか**
答え: 車輪ごとの速さと、そこから出る前進の速さ `v` と位置。IMU の gz で回る速さは測れますが、ax を 2 回積分した位置はすぐずれます。

## 01 章 S2R と R2S

**1. τ = 0.1 s、K = 20、u = 0.5 の ω**
答え: 十分経つと `K·u = 10 rad/s`。0.1 秒後は `10·(1 − e^{−1}) = 6.32 rad/s`。

**2. r = 0.02、b = 0.1、ωR = 10、ωL = 5 の v と ωz**
答え: `v = 0.02·(10+5)/2 = 0.15 m/s`、`ωz = 0.02·(10−5)/0.1 = 1.0 rad/s`。
つまずき: `b` は左右の車輪の間隔（半分ではない）。

**3. domain randomization で振るもの 3 つと幅**
答え（例）: モーターのゲイン、時定数、ジャイロのバイアス。幅は実機（または同じ機体）を何回か同定し、ばらつきの最大・最小を少し広げて決めます。いまのコードの幅は `src/physlearn/randomize.py` の `SPREAD` にあります（`motor_gain` は公称の −30 %〜+14 %、`motor_tau` は −14 %〜+60 %、`deadband` は ±0.03、`gyro_bias` は ±0.02 rad/s。06 章）。

## 02 章 IMU

**1. ±2 g で静止時の az の生の値**
答え: 約 16393（`1000 / 0.061 = 16393.4`）。

**2. gz の平均 0.004 rad/s を引かずに 5 分積分**
答え: `0.004 × 300 = 1.2 rad ≈ 68.75 度`（Python で `math.degrees(1.2) = 68.75`）。標準偏差 0.002 は 1 サンプルごとの揺れで、積分ではほぼ打ち消し合うので、ずれの大半はバイアスから来ます。

**3. 机の傾きは静止ログの何を変えるか、バイアスと見分けられるか**
答え: `ax`・`ay` の平均が 0 からずれます（重力の一部が載る）。ジャイロは重力を感じないので、傾いても gz の平均は変わりません。だから見分けられます。加速度のずれは傾き、gz の平均のずれはバイアスです。11 章の `still` が出す `roll`・`pitch` がこの傾きです。

## 03 章 ハードウェアとファームウェア

実機の代わりに代役で解きました（実機では確かめていません）。

**1. 静止ログの gz の平均・標準偏差と 60 秒のずれ**

つまずき: 代役の真のバイアスは 0.006 です。10 秒の平均では 0.001 ほど外れます（11 章 演習 2 の Allan 偏差の大きさと合う）。

**2. u = +0.5 の段の 63 % 時刻と、最終値が u に比例するか**
答え（`physlearn sim-log id.csv --plant hidden`、1700 行。u = +0.2・+0.35・+0.5 の最初の段、最初の静止の後半の平均 0.078 を引いた gz の、段の後ろ 0.3 s の平均）:

| u | gz の最終値 | 最終値 / u | 63 % 時刻 |
| --- | --- | --- | --- |
| 0.2 | 0.397 | 1.98 | 0.17 s |
| 0.35 | 1.577 | 4.51 | 0.18 s |
| 0.5 | 2.760 | 5.52 | 0.18 s |

比例しません。最終値を u の 1 次式で結ぶと傾き 7.88、gz が 0 になる u が 0.150 で、デッドバンドがあると分かります。代役 (`HIDDEN`) の真値は `motor_tau = 0.2`、`deadband = 0.15`、`gyro_bias = 0.08`、`yaw_gain = 8` です。63 % 時刻が 0.2 s より少し短く出るのは、100 Hz の刻みと雑音（0.015 rad/s）のためです。
つまずき: gz にはバイアスが乗っているので、最初の静止区間の平均を引いてから比べます（引かずに最終値 0.474 / 1.655 / 2.838 のまま直線を引くと、切片が 0.140 になりバイアスの分だけ小さく出ます）。

**3. 基板を 180° 回したときの `--axes`**
答え: `--axes=y,-x,z`（機体の x は基板の y、機体の y は基板の −x、z はそのまま）。
考え方: 3.7 節の基準の付け方（USB-C が前、部品面が上）は `--axes=-y,x,z` です。基板を水平のまま 180° 回すと、基板の x・y の向きが機体に対して両方とも逆になるので、基準の式の x と y の符号を両方反転します（`-y,x,z` → `y,-x,z`）。z は回さないのでそのままです。
確かめ（偽の XIAO を `--axes=y,-x,z` で立て、`link` の `SerialPlant` で前進 `Command(0.4, 0.4)` の最初の 0.3 s の `ax` の平均を見た）: `--axes=y,-x,z` で +0.15 m/s²、基準の `-y,x,z` のままだと −0.18 m/s² と符号が逆、`x,y,z`（付け替えなし）だと +0.004 で、加速度が別の軸に出ていて見えません。
つまずき: 水平のままの回転では重力（az）が変わらないので、静止ログだけでは `--axes` が合っているか分かりません。動かして ax の向きを見ます。実機では確かめていません。`hwcheck axes` は偽の XIAO では水平の姿勢しか出せず、1 姿勢目で止まります（12 章）。

## 05 章 Real2Sim

基準（公称 `Params()`、seed 0、`sim-log` と同じ 17 s・1700 行）の同定: `yaw_gain` 12.0034、deadband 0.05、tau 0.0804、bias −0.0014、noise 0.0103、drift −0.0001。変更はすべてスクリプトの中で差し替えて入れました。

**1. 最初の静止を 0.1 s に縮める**
答え: `sysid` は `ValueError`（「最初に静止区間 (指令 0) が 20 行以上いる」）で止まります。0.1 s は 10 行しかありません。
なぜ: バイアスと雑音を最初の静止区間から測るので、短すぎる静止で黙って誤った値を返さないよう検査しています。

**2. ステップの振幅をすべてデッドバンドより小さく**
答え（振幅 ±0.02・0.03・0.045、デッドバンド 0.05）: `{'gyro_bias': -0.0014, 'gyro_noise': 0.0103}` だけが返り、`yaw_gain`・deadband・tau は返りません（CLI の `physlearn sysid` は「動いたステップが 2 つ未満なので…推定しない」と書き足します）。
なぜ: どの段も gz が雑音の 10 倍を超えず「動いた」段が 2 つ未満になるので、静止だけのログとして扱われます。

**3. `Params(gyro_noise=0.05)`**
答え: 大きくずれるのは gyro_bias です。seed 0〜2 で、雑音 0.01 のとき bias −0.0014 / −0.0011 / −0.0033、雑音 0.05 で −0.0068 / −0.0053 / −0.0167（真値 0）。`yaw_gain` は 12.002〜12.003（雑音 0.01）→ 11.970〜12.002（雑音 0.05）、deadband は 0.050 → 0.049〜0.050、tau は 0.0804 のまま。ゲインもデッドバンドもモデルの当てはめで決めるので、雑音が 5 倍でもほとんど動きません。bias は静止区間の後半 50 サンプルの平均なので、誤差が雑音に比例します（5 倍の雑音で 5 倍前後）。`drift` は ±0.001 以内で 0 のままです。
つまずき: seed 3 本だけの比較です。

## 06 章 Sim2Real

**1. `design()` に FF (r / K) を戻す**
答え: 行き過ぎが仕様の 10 % を大きく超えます。tc = 0.15 で 0.1 % → 18.9 %（整定 0.43 → 0.51 s）、tc = 0.10 で 0.15 % → 22.4 %（整定 0.26 → 0.43 s）。コードのコメント（FF で零点ができて行き過ぎる）のとおりです。

**2. `SPREAD` の時定数の幅とバイアスの幅**
答え: 公称の `Params()`・t_c = 0.08・`randomize.evaluate(p, 0.08, n=50)` で、通過率は次のとおり。

| `SPREAD` | 通過率 |
| --- | --- |
| 既定（`motor_tau` (−0.14, +0.60)、`gyro_bias` ±0.02） | 1.0 |
| `motor_tau` (−0.60, +0.60) | 1.0 |
| `motor_tau` (−0.14, +1.20) | 1.0 |
| `gyro_bias` ±0.1 rad/s | 0.46 |
| `gyro_bias` ±0.05 rad/s | 0.98 |

```python
from physlearn import randomize as R
from physlearn.sim import Params
old = dict(R.SPREAD)
R.SPREAD["motor_tau"] = (-0.60, +0.60); print(R.evaluate(Params(), 0.08, n=50))   # 戻してから次へ
R.SPREAD.update(old); R.SPREAD["gyro_bias"] = 0.1; print(R.evaluate(Params(), 0.08, n=50))
```

なぜか: 制御器は誤差を `e = r − (gz − bias)` で作り、`bias` には設計に使った公称の値（0）を引きます。本当のバイアスが b なら、積分が gz を r に合わせるので、真のヨー角速度は r − b に落ち着きます。b が仕様の定常偏差 0.05 rad/s を超えると、どんなゲインでも定常偏差で外れます（±0.1 の幅で、その外にある個体が 5 割ほど）。時定数のずれは、積分が残りを消すので速さが少し変わるだけで、定常偏差には残りません。tc = 0.08 は、時定数が公称の 1.6 倍（+0.60）になっても整定 0.6 s に収まります。

**3. `SafetyGate(max_rate=2.0)` での duty の増え方**
答え: dt = 0.01 で 1 回ごとに 0.02 ずつ増えます（右の duty が 0.02, 0.04, 0.06, 0.08, 0.10。左は符号が逆）。
公称の `Params()` では K_yaw = 12.0（`Params().yaw_gain()`）、d = 0.05 なので、要る duty は u = 3 / 12 + 0.05 = 0.30。届くまで 0.30 / 2.0 = 0.15 s です。

```python
from physlearn.control import SafetyGate
from physlearn.api import Command, Obs
g = SafetyGate(max_rate=2.0); o = Obs(0, 0, 0, 9.8, 0, 0, 0)
for _ in range(5): print(g(Command(-0.5, 0.5), o, 0.01))
```

0.15 s は整定の仕様 0.6 s より短いので、届くこと自体は間に合います。ただしその間も積分は溜まり続けるので、t_c を短くした制御器では行き過ぎが出ます。

閉ループで測る（`control.run(SimPlant(Params()), design(Params(), 0.08), gate=SafetyGate(max_rate=...))`、公称の `Params()`・seed 既定）:

| `max_rate` | tc | 整定 | 行き過ぎ | 仕様 |
| --- | --- | --- | --- | --- |
| 10（既定） | 0.08 | 0.19 s | 0.2 % | OK |
| 2 | 0.08 | 0.55 s | 30.7 % | NG（行き過ぎ） |
| 2 | 0.15 | 0.26 s | 1.6 % | OK |
| 2 | 0.20 | 0.49 s | 0.1 % | OK |

原因は積分の溜めすぎです（確かめた）。`max_rate=2` では、真のヨー角速度が初めて 3 rad/s に届く 0.22 s の時点で積分が 0.46 まで溜まっていて（定常で要るのは 3 / 12 = 0.25）、そのあと 3.9 rad/s まで行き過ぎてから戻ります。`max_rate=10` では積分は 0.25 を超えません。ゲートが duty の増え方を遅らせる間、制御器は誤差が残っていると見て積分を増やし続けるためです。ゲートを通すと制御器から見たモーターは遅く見えるので、設計の t_c もそれに合わせて緩めます（t_c = 0.15 以上）。

## 07 章 ループ

基準の `uv run physlearn loop-demo`: 前は tc 0.08、整定 0.64 s、行き過ぎ 5.8 %、定常偏差 0.081 rad/s で NG。同定は `yaw_gain` 8.011（真値 8）、deadband 0.15、`motor_tau` 0.201（真値 0.2）、bias 0.08。後は tc 0.2、sim での通過率 42 %、整定 0.51 s、行き過ぎ 0.1 % で OK。
`HIDDEN` を書き換える問は、`physlearn.HIDDEN` を差し替えて `loop_demo()` を呼びました。

## 08 章 MuJoCo

`mujoco_plant.MODEL` の xml の文字列を書き換え、`MujocoPlant(xml=...)` に渡して解きました（リポジトリの xml は直していません）。

**1. 車体の質量 0.25 → 0.5 kg**
答え: 時定数は約 1.7 倍に延び、定常の gz はほとんど変わりません。定常は「トルクと粘性が釣り合う点」で決まり、慣性は釣り合いに入らないからです。慣性は釣り合うまでの速さだけを変えます。

| 質量 | yaw_gain | motor_tau | 定常 gz (u = 0.5) |
| --- | --- | --- | --- |
| 0.25 kg | 17.974 | 0.0704 | 8.978 |
| 0.5 kg | 17.967 | 0.1198 | 8.977 |

（`sim-log --plant mujoco` と同じ実験を `sysid` にかけた値。定常 gz は雑音なしの MuJoCo で u = 0.5 を 3 s 与えた最後の 0.3 s の平均。`--plant mujoco` のログには、ジャイロのバイアス 0.02 が足されます。）
13 章の式（`motor.py`）で予想した τ は 0.0673 → 0.1179 で、測った値と近いです。0.0673 が 0.0704 より小さいのは、式が車輪を球、車体を箱として慣性を足し合わせた近似だからです。

**2. 静止中の gz の平均でバイアスを推定**
答え: 30 秒の静止で平均 0.020018（真値 0.02）、標準偏差 0.005025。平均の誤差は `σ/√N` で減るので、1σ で 0.001 に収めるには `(0.005/0.001)² = 25` サンプル、つまり 0.25 秒あれば足ります。区間ごとの平均の誤差 (rms) は 0.25 s で 0.00098、1 s で 0.00043、10 s で 0.00019 でした。
つまずき: `sysid.identify` は最初の 1 秒の静止のうち後半 50 行だけを使います。このログでは推定 0.0193 で、0.0007 外れました。

**3. sim-to-sim（MuJoCo のログで numpy の sim を同定して重ねる）**
答え: 定常値と立ち上がりはよく合います。同定値は `yaw_gain` 17.974（`motor_gain` に直すと 29.96）、tau 0.0704、deadband 0（0.0）、bias 0.0193。同じ指令で numpy の sim を回すと全体の RMSE は 0.0172 rad/s です（雑音 0.005 rad/s の 3.4 倍。立ち上がりの形が一次遅れと違うため。14 章）。定常（段の後ろ 0.3 s の平均）は ±0.5 で 8.998 / 9.007、±0.35 で 6.304 / 6.310、±0.2 で 3.611 / 3.614（MuJoCo / numpy）、63 % 時刻はどちらも 0.06 s。
±0.2 の段も合います。後半 0.5 s の gz は +0.2 の段が 3.611、−0.2 の段が −3.571（予測 3.6 にバイアス 0.02 を足し引きした値）で、MuJoCo にデッドバンドはありません（08 章「小さい duty でも回るか」）。numpy の sim も 3.614 / −3.576 で、同じように回ります。

## 09 章 安全

**1. ウォッチドッグを PC 側だけに置くと**
答え: PC がフリーズした、USB が抜けた、PC のプログラムが落ちた、のときに役に立ちません。止める命令を送る側が止まっているからです。だからスケッチ側にも置きます（200 ms。12 章 演習 2 で確かめた）。

**2. 1 step 0.05、step 20 ms で 0 → 0.5**
答え: `0.5 / 0.05 = 10 step`、`10 × 20 ms = 0.2 秒`。

**3. sim にも変化率の制限を入れるべきか**
答え: 入れるべきです。実機だけに入っていると、実機のほうが遅れが大きく見え、それ自体が reality gap になります。sim と実機で同じ関数を通すのがいちばん確実です。

## 10 章 次の一歩

**1. エンコーダーで何が測れるようになるか**
答え: 車輪ごとの速さと、`v = r(ωR + ωL)/2` を積分した走った距離・位置。ただし車輪が滑ると、車輪は回っても車体は進まないので、位置はずれます。

**2. 強化学習の方策を試す前に厳しくするゲート**
答え: duty の上限と変化率の制限。方策は学習で見なかった状態で極端な指令や急な切り替えを出すことがあるからです。ウォッチドッグは方策によらずそのまま残します。

**3. ROS 2 のメッセージにするとき単位と座標の約束をどこに書くか**
答え: メッセージの定義ファイル（`.msg`）のフィールドのそばのコメント。いまの `src/physlearn/api.py` の `Command` / `Obs` と同じやり方です。ROS 2 の慣習（REP 103: SI 単位、x 前・y 左・z 上）に合わせると、ほかの部品とつなぎやすくなります。

## 13 章 モーターの物理

`motor.py` を呼んで計算しました（モーター定数は仮の値）。`motor.mujoco_model()` は b = 0 の `Motor` と `J_eff = 1.1217e-4 kg m²` を返します。

**1. 減速比 n を 2 倍**
答え: b = 0 なら K は 1/2 倍、τ は 1/4 倍。`first_order(replace(m, n=...), j_eff)` で n = 1 は (K, τ) = (30.0, 0.0673)、n = 2 は (15.0, 0.01683)。
なぜか: `K = n·Kt·V/(n²·Kt·Ke)` は n に反比例し、`τ = J_eff·R/(n²·Kt·Ke)` は n² に反比例します。

**2. 荷物 0.1 kg を前端 (x = +0.06) に**
答え: 中心に載せたときより `m·x² = 0.1 × 0.06² = 3.6e-4 kg·m²` だけ多く増えます。荷物を点とみなすと、中心で +0、前端で +3.6e-4。章の表のように荷物を箱の形（車体の箱と同じ 0.12 × 0.09 m）とみなすと、中心で +1.875e-4、前端で +5.475e-4（元の I_yaw は 5.83e-4）。τ は荷物なし 0.0673 s、中心 0.0876 s、前端 0.1264 s（点なら前端 0.1062 s）。
つまずき: x = +0.06 は車体の箱のちょうど端です。点とみなすか箱とみなすかで答えが変わります。

**3. 電池の内部抵抗を足す（omc）**
答え: `DCMotorPivot.mo` には内部抵抗のパラメーター `Rbat`（巻線と直列、既定 0）があります。`simulate(DCMotorPivot, stopTime = 0.5, numberOfIntervals = 5000, simflags="-override Rbat=0.5")` で走らせると、t = 0.5 s のヨー角速度は 8.9657（Rbat = 0 は 8.9946）、t = 0.0898 s で 5.6900（定常 9.0 の 0.632 倍）でした。`motor.first_order` の式でも K = 30 → 30、τ = 0.0673 → 0.0897 s で合います。
つまり、粘性 b = 0 のこのモデルでは、内部抵抗は K を変えず（無負荷では電流が流れないので電圧が落ちない）、τ だけを `(R + Rbat)/R` 倍（R = 1.5 Ω、Rbat = 0.5 Ω なら 4/3 倍）に延ばします。K が下がるのは、粘性や負荷で定常にも電流が流れるときです。

## 14 章 当てはまりの診断

`python -m physlearn.compare`（`fit`）の中身を Python から呼んで解きました（`compare.fit(log, params)`）。ログは `physlearn sim-log`、パラメータは `sysid` の結果（`HIDDEN` のログから `yaw_gain` 8.006・デッドバンド 0.15・時定数 0.201、MuJoCo のログから `yaw_gain` 17.974・デッドバンド 0・時定数 0.0704）です。

**1. `HIDDEN` のデッドバンドだけを 0.1 ずらした sim で `fit`**
答え: 判定は「ゲイン（かデッドバンド）がずれている」です。この道具はゲインと時定数しか試していないので、デッドバンドのずれはゲインのずれに見えます。
同定したパラメータのデッドバンドだけを 0.15 → 0.25 にして、同じ `HIDDEN` のログに当てると、RMSE は雑音の 28.8 倍（立ち上がり 25.7 倍、定常 32.5 倍）。残差と指令の相関 +0.89。「ゲインだけを 1.55 倍にすると残差の 76 % を説明できる」「時定数だけを 0.39 倍にすると 11 %」と出ます。0.05 に下げても（−0.1）同じ判定で、ゲインを 0.70 倍にすれば 89 % を説明できると出ます。
なぜデッドバンドがゲインに見えるのか: 定常の差（実 − sim）が、u = 0.35 でも 0.5 でも約 0.79 rad/s と同じです。デッドバンドがずれると「u のうち動きに効く分」が一定量変わるので、定常値のずれは u によらず `K × 0.1 = 0.8` rad/s です。u = 0.2 だけは 0.40 で、ずらした sim ではまだ回らない（0.2 < 0.25）ぶん、`K × (0.2 − 0.15)` だけが残ります。ゲインのずれなら u に比例するはずなので、定常の差が u に比例しない（u = 0.35 と 0.5 で同じ）のがデッドバンドの目印です。この道具は「ゲインで説明できる割合」が 76 % で 100 % にならないところまでしか言えません。
同じことを、デッドバンド 0.25 の `SimPlant` を実機に見立てて古い同定で当てても、同じ判定でした（ゲイン 0.62 倍で 90 %）。

**2. (b) の MuJoCo で、時定数を 0.5 倍・2 倍にした JSON を `fit`**
答え: 立ち上がりの RMSE は時定数を外すと大きく悪くなります。

| 時定数 | 立ち上がり RMSE | 雑音の何倍 | 全体 | 判定 |
| --- | --- | --- | --- | --- |
| 0.5 倍 | 0.904 | 176 | 93.7 倍 | 時定数（か遅延）がずれている |
| 1 倍（sysid） | 0.0319 | 6.2 | 3.5 倍 | ゲインでも時定数でも説明できない → 式の形が違う |
| 2 倍 | 1.244 | 243 | 134.6 倍 | 時定数（か遅延）がずれている |

一次遅れのままでは、立ち上がりの残差を雑音の 2 倍以下（0.0103 rad/s 以下）にできません。時定数を 0.5〜1.5 倍で 0.05 刻みに振って探しても、立ち上がりの RMSE が最小になるのは sysid の値（1 倍）で、その RMSE は 0.0319（雑音の 6.2 倍）です。時定数を変えても、形の違い（出だしが遅く、あとで速い）は消えないからです。

**3. MuJoCo の代役で、デッドバンドだけを 0.05 に戻して設計し直す**
答え: 0.08 s には戻りません。整定は 0.22 s → 0.13 s に縮みますが、まだ遅いままです。
方法（`loop_demo` を書き換えない）: `loop_demo` の中身を呼び出し側で再現します。`make_plant("mujoco", seed=1000)` を代役にし、同定した `Params` の `deadband` だけを `dataclasses.replace` で 0.05 にして、`randomize.tune` で tc を決め、`control.design` → `control.run` → `control.metrics` で測ります。

| 同定そのまま（deadband 0） | 0.22 s | 0.0 % | 0.001 rad/s |

## 15 章 実機の代役が教えるずれ

`mismatch.HardPlant`（`HIDDEN` に現象を足したもの）で `identify(as_log(sim_log(plant)))` を呼びました（`mismatch.py` の `one` と同じ呼び方）。真値は `yaw_gain` 8、時定数 0.2、デッドバンド 0.15、バイアス 0.08。

**1. `delay` を 0.01・0.04・0.08 s**
答え: 同定の τ は遅延の分だけ増えます。

| delay | 同定の τ | τ の増え（0.2 に対して） | 増え / delay | 同定の `yaw_gain` |
| --- | --- | --- | --- | --- |
| 0（`HIDDEN`） | 0.2011 | +0.001 | — | 8.006 |
| 0.01 s | 0.2120 | +0.012 | 1.2 | 8.061 |
| 0.04 s | 0.2487 | +0.049 | 1.2 | 8.242 |
| 0.08 s | 0.2995 | +0.100 | 1.2 | 8.496 |

τ の増えは遅延の約 1.2 倍です（一次遅れ 1 つに、むだ時間を押し込んで当てはめるので、遅延がそのまま τ の増えになるわけではありません）。ゲインも遅延とともに少し大きく出ます（遅延 0.08 s で +6 %）。0.2 s の時定数に 0.08 s の遅延が加わると、τ は 5 割増しに見えます。

**2. `sag` を 0.1・0.27・0.4 で `drift`**
答え: `drift` は `sag` に比例しません。

| sag | `drift` | 同定の `yaw_gain` | 同定の τ | `drift` / sag |
| --- | --- | --- | --- | --- |
| 0 | −0.0003 | 8.006 | 0.2011 | — |
| 0.1 | −0.0529 | 7.256 | 0.1984 | 0.53 |
| 0.27 | −0.1562 | 6.026 | 0.1984 | 0.58 |
| 0.4 | −0.2501 | 5.054 | 0.1958 | 0.63 |

予想の立て方: ゲインは 0 s から 13 s（`SAG_T`）まで直線で `1 − sag` まで落ち、その後は一定です。`drift` は「最後の 2 つの 0.35 の段（13〜17 s）」と「最初の 2 つ（5〜8 s、平均の時刻 6.5 s = 13 s の半分）」のゲインの比 − 1 です。最初の 2 つのゲインは `1 − sag/2`、最後の 2 つは `1 − sag` なので、`drift ≈ (1 − sag)/(1 − sag/2) − 1 = −(sag/2)/(1 − sag/2)`。sag = 0.1、0.27、0.4 で −0.053、−0.156、−0.250 と、走らせた値と合います。分母に sag が入るので比例ではなく、sag が大きいほど `drift / sag` が大きくなります。
最後の 2 つのステップが 13 s より後なのは、実験が 17 s あるからです。`mismatch.py` の `SAG_T = 13` とそのコメント（「同定の実験 1 回分」）は、実験が 13 s だった頃の値のままです【コードの不整合。直していない】。この解答の式は、`SAG_T = 13` のコードで走らせた値です。
同定の `yaw_gain` は、`sag` が大きいほど小さく出ます（実験全体の平均より、大きな段が後ろにあるため）。時定数はほとんど動きません。

**3. `tc = 0.3` が通るのは電池が新品のときだけ。`SPREAD["motor_gain"]` はいくつか**
答え（`mismatch loop` の値）: 全部入りの代役では、同定が `yaw_gain` 6.05・τ 0.245・デッドバンド 0.136 になり、tc = 0.3 は「電池を新品に」だけ OK（整定 0.56 s）で、「電池そのまま」は定常偏差 0.373 rad/s で NG でした。
考え方（`sag` だけの `HardPlant(sag=0.27)` で数えた概算）:

- 13 章の表は公称（6.0 V）を 1 として、消耗で −27 %、新品で +7 % です。`SPREAD["motor_gain"]` の (−0.30, +0.14) はこれを丸めたものです。
- ただし設計に使うのは「同定した `yaw_gain`」で、これは実験の途中で電池が落ちながら測った値です。`sag = 0.27` の代役では、同定は 6.03 で、電池が減っていない代役の 8.01 の 0.753 倍でした。
- そこで、同定した値を 1 として見ると、新品は 1 / 0.753 = 約 +33 %、消耗（1 − 0.27 = 0.73）は 0.73 / 0.753 = 約 −3 % です。幅（下から上まで）は −3 %〜+33 % で、−30 %〜+14 % とは位置が違います。

つまり、同定の実験が電池の落ちる最中なら、`motor_gain` の上側（電池を替えたときに上がる分）は +14 % では足りず、+30 % 前後が要る、というのが計算の答えです。下側はほとんど要りません。幅の合計（約 0.36〜0.44）はほぼ同じで、公称を中心に置くか、同定の値を中心に置くかで位置が変わります。同定の `drift` が 0 に近ければ（電池が実験のあいだ変わらなければ）、公称基準の (−0.30, +0.14) のままで構いません。実機の電池の減り方は【未確認】で、この計算は `sag` だけを入れた代役の概算です。`SPREAD` の書き換えは、この解答ではしていません。

## 16 章 筐体と質量特性

`python -m physlearn.cad`（`cad.mass_props`・`cad.to_mjcf`・`cad.spin`・`cad.tau_63`）を呼んで解きました。車体は `DEFAULT_PARTS`（箱 0.25 kg + 車輪 2 × 0.02 kg）、電池は 0.1 kg の箱（0.06 × 0.06 × 0.015 m、z = 0.0175）です。車輪半径とトレッドは `cad/dimensions.csv` の「sim の今の値」（0.030・0.100 m、assumed）。SolidCraft の CLI は使っていません。

`python -m physlearn.cad` の出力:

```
既定の車体: 質量 0.290 kg、重心 x +0.000 m、Izz 5.831e-04 kg m^2
電池 0.1 kg を x=+0.00 m: Izz 6.431e-04、MuJoCo の τ(63%) 0.078 s
電池 0.1 kg を x=+0.04 m: Izz 7.621e-04、MuJoCo の τ(63%) 0.090 s
電池なし: MuJoCo の τ(63%) 0.072 s
```

**1. 電池を中心から後ろへ 4 cm（x = −0.04 m）**
答え: Izz は 7.621e-4 kg m²、MuJoCo の τ(63 %) は 0.090 s で、前へ 4 cm（x = +0.04）ずらしたときと同じです。中心に置いたとき（6.431e-4、0.078 s）より Izz が 1.19e-4 増え、τ が 0.012 s 延びます。電池なしの 0.072 s に対しては 0.018 s 延びます。増え方 1.19e-4 は、車体 0.29 kg と電池 0.1 kg が 4 cm 離れたときの `m·M/(m+M)·x² = 0.1 × 0.29 / 0.39 × 0.04² = 1.19e-4`（重心回りの Izz なので、`m·x² = 1.6e-4` ではなくこの換算質量の形になる）と合います。
なぜ同じか: 慣性は距離の 2 乗なので、前後の向きに依りません。前に置くと重心が前に 1.03 cm、後ろに置くと後ろに 1.03 cm 動きますが、どちらも Izz の値は同じです。ただし、この問の MuJoCo の τ は IMU と車輪の位置を変えず、電池の質量だけを足した結果です。

**2. IMU を左へ 2 cm（y = 0.02）にしてその場旋回（u = 0.6）**
答え: ay に出ます。式: 回転の中心から IMU までの位置が `(0, y)` で、角速度 ω で回っていれば、向心加速度は中心に向かって `ω²y`、つまり機体の座標で `ay = −ω²y`（IMU が左にあれば、中心は右）です。ax には、角加速度 α の間だけ接線の加速度 `−α·y` が出ます。
確かめ: 定常（ω = 10.77 rad/s）で `ay` = −2.321 m/s²（式の `−ω²y = −2.321`）、`ax` = 0.000。回り始めの 0.1 s は `ax` が −0.77〜−3.14 m/s² まで出て、そのあと 0 に戻ります（α が正で y が正なので負）。IMU を中心（y = 0）に置けば、どちらも 0 です。
参考: 前へ 4 cm（x = 0.04）では `ax` = −4.643 m/s²（式の `−ω²x` と同じ）で、章の本文の例と同じです。

**3. 電池をトレッドの外側（車輪より外）に置くと**
答え:

- 慣性: 回転の中心（車輪軸の中点）から遠いほど Izz への寄与は `m·y²` で効きます。0.1 kg を y = 0.08 m（車輪の外側 3 cm）に置くと、`0.1 × 0.08² = 6.4e-4` で、車体の元の Izz（5.83e-4）より大きくなります。同じ電池を y = 0 に置いたときは自身の箱の分 1.2e-4 程度です。τ がそれだけ延びます（MuJoCo で測っていません【未確認】）。
- 車輪にかかる重さ: 重心が電池の側に寄ります。y = 0.08 の電池で、重心は y = 0.1 × 0.08 / 0.39 = 0.0205 m（約 2 cm）電池の側に動きます。キャスターは y = 0 の線上にあるので無視して、間隔 0.1 m の 2 つの車輪だけで支えるとすると、電池側の車輪が約 70 %、反対側が約 30 % を受けます【手計算の概算。MuJoCo では測っていません】。軽い側の車輪は路面を押す力が小さく滑りやすく、左右で実質のゲインが変わります（15 章の `lr`）。電池をもっと外に置いて重心が車輪の間（|y| < 0.05）を出ると、車体が傾いて倒れます。

走らせたのは演習 1・2 の数値だけで、演習 3 の重さの配分は手計算（概算）です。
