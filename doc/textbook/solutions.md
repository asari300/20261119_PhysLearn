# 演習の解答集

各章の末尾の演習の解答です。手を動かす問は、2026-11-19 の main のコードで実際に走らせ、その出力の数値を書いています。実機は使っていません。実機が要る問は、偽の XIAO（12 章）か代役（`physlearn sim-log --plant hidden`、`imu.stand_in`）で解き、そのことを書いています。

- 乱数の種や代役の値が変われば、細かい数値も変わります。桁と傾向を見てください。
- 試しのスクリプトは載せず、要点の数行だけを書きます。
- 14〜16 章は未収録です（書かれている最中のため）。

## 00 章 全体像

**1. 画面で作って実物で動かすもの**
答え（例）: ドローンの飛行制御。差は、重さ（電池を替えると変わる）、プロペラの曲がり、風、電池の電圧が下がること、センサーの雑音と遅れから生まれます。

**2. 制御器が相手を知らなくてよいのはなぜ**
答え: 制御器は `Command` を出して `Obs` を受け取るだけで、相手が `Plant` の約束（`reset()` と `step(cmd, dt)`）を守っていれば中身を見ないからです。`src/physlearn/api.py` の型と、`sim.SimPlant`・`mujoco_plant` がどちらも同じ形を実装していることで確かめられます。

**3. エンコーダーを使わないと何が測れないか**
答え: 車輪ごとの速さと、そこから出る前進の速さ `v` と位置。IMU の gz で回る速さは測れますが、ax を 2 回積分した位置はすぐずれます。

## 01 章 S2R と R2S

**1. τ = 0.1 s、K = 20、u = 0.5 の ω**
答え: 十分経つと `K·u = 10 rad/s`。0.1 秒後は `10·(1 − e^{−1}) = 6.32 rad/s`。

**2. r = 0.02、b = 0.1、ωR = 10、ωL = 5 の v と ωz**
答え: `v = 0.02·(10+5)/2 = 0.15 m/s`、`ωz = 0.02·(10−5)/0.1 = 1.0 rad/s`。
つまずき: `b` は左右の車輪の間隔（半分ではない）。

**3. domain randomization で振るもの 3 つと幅**
答え（例）: モーターのゲイン、時定数、ジャイロのバイアス。幅は実機（または同じ機体）を何回か同定し、ばらつきの最大・最小を少し広げて決めます。いまのコードの幅は `src/physlearn/randomize.py` の `SPREAD` にあります（時定数 ±30 %、`gyro_bias` ±0.02 rad/s など）。

## 02 章 IMU

**1. ±2 g で静止時の az の生の値**
答え: 約 16393（`1000 / 0.061 = 16393.4`）。

**2. gz の平均 0.004 rad/s を引かずに 5 分積分**
答え: `0.004 × 300 = 1.2 rad ≈ 68.75 度`（Python で `math.degrees(1.2) = 68.75`）。標準偏差 0.002 は 1 サンプルごとの揺れで、積分ではほぼ打ち消し合うので、ずれの大半はバイアスから来ます。

**3. 机の傾きは静止ログの何を変えるか、バイアスと見分けられるか**
答え: `ax`・`ay` の平均が 0 からずれます（重力の一部が載る）。ジャイロは重力を感じないので、傾いても gz の平均は変わりません。だから見分けられます。加速度のずれは傾き、gz の平均のずれはバイアスです。11 章の `still` が出す `roll`・`pitch` がこの傾きです。

## 03 章 ハードウェアとファームウェア

**2. u = +0.5 の段の 63 % 時刻と、最終値が u に比例するか**

| u | gz の最終値 | 最終値 / u | 63 % 時刻 |

つまずき: gz にはバイアスが乗っているので、最初の静止区間の平均を引いてから比べます。

**3. 基板を 180° 回したときの `--axes`**

## 04 章 numpy の sim

**1. `Params(deadband=0.2)` で u = 0.15 と 0.3**
答え: 予想は `yaw_gain·max(0, u − 0.2)`、`yaw_gain = 2·0.016·30/0.08 = 12`。u = 0.15 は 0、u = 0.3 は 1.2 rad/s。
確かめ（その場旋回 `Command(-u, u)` を 1 秒ずつ）: `yaw_rate` = 0.0 と 1.2。

**2. left 0.3, right 0.5 で ay ≈ v·ψ'**
答え: 合います。2 秒後に v = 0.168 m/s、ψ' = 1.2 rad/s、`v·ψ' = 0.2016`。後半 1 秒の ay の平均は 0.2038（雑音 0.05 が乗る）。

**3. `motor_tau` 0.08 → 0.3 で 63 % 時刻**
答え: 時定数と同じだけ延びます。雑音を 0 にして測ると 0.08 s → 0.30 s。

## 05 章 Real2Sim

基準（公称 `Params()`、seed 0）の同定: K = 12.0009、deadband 0.05、tau 0.0804、bias −0.0014、noise 0.0103。変更はすべてスクリプトの中で差し替えて入れました。

**1. 最初の静止を 0.1 s に縮める**
答え: `sysid` は `ValueError`（「最初に静止区間 (指令 0) が 20 行以上いる」）で止まります。0.1 s は 10 行しかありません。
なぜ: バイアスと雑音を最初の静止区間から測るので、短すぎる静止で黙って誤った値を返さないよう検査しています。

**2. ステップの振幅をすべてデッドバンドより小さく**
答え（振幅 ±0.02・0.03・0.045、デッドバンド 0.05）: `{'gyro_bias': -0.0014, 'gyro_noise': 0.0103}` だけが返り、K・deadband・tau は返りません。
なぜ: どの段も gz が雑音の 10 倍を超えず「動いた」段が 2 つ未満になるので、静止だけのログとして扱われます。

**3. `Params(gyro_noise=0.05)`**
答え: 大きくずれるのは gyro_bias です。seed 0〜2 で、雑音 0.01 のとき bias −0.0014 / −0.0011 / −0.0033、雑音 0.05 で −0.0068 / −0.0053 / −0.0167（真値 0）。K は 12.001〜12.041、deadband は 0.0502〜0.0514 で少し、tau は 0.0804 のまま。bias は静止区間の 50 サンプルの平均なので、誤差が雑音に比例します。
つまずき: seed 3 本だけの比較です。

## 06 章 Sim2Real

**1. `design()` に FF (r / K) を戻す**
答え: 行き過ぎが仕様の 10 % を大きく超えます。tc = 0.15 で 0.1 % → 18.9 %（整定 0.43 → 0.51 s）、tc = 0.10 で 0.15 % → 22.4 %。コードのコメント（FF で零点ができて行き過ぎる）のとおりです。

**2. `SPREAD` の時定数の幅 ±30 % → ±60 %**
答え: ほとんど変わりません。選ばれる tc は 0.08 のまま、通過率も 100 % のまま（n = 50）。

| tc | ±30 % | ±60 % |
| --- | --- | --- |
| 0.08 | 1.0 | 1.0 |
| 0.10 | 1.0 | 1.0 |
| 0.15 | 0.98 | 0.98 |
| 0.20 | 0.54 | 0.52 |
| 0.25 | 0.0 | 0.02 |

公称の tau = 0.08 は制御の速さに比べて短いので、その幅を広げても効きにくいです。

**3. 安全ゲートの `max_rate` を 2 /s に**
答え: 満たします。ただし速い tc は使えなくなります。tc = 0.08 では行き過ぎ 0.19 % → 30.7 % で外れ、tc = 0.15 は整定 0.26 s・行き過ぎ 1.55 % で通ります。tune の結果は (tc 0.08, 通過率 1.0) → (0.15, 1.0)。変化率の制限で u が遅れる間に積分が溜まり、行き過ぎます。
つまずき: `max_rate` は CLI からも `run()` の引数からも変えられません。`SafetyGate` の既定値を差し替えて試しました。

## 08 章 MuJoCo

`mujoco_plant.MODEL` を、写した xml に差し替えて解きました（リポジトリの xml は直していません）。

**1. 車体の質量 0.25 → 0.5 kg**
答え: 時定数は約 1.7 倍に延び、定常の gz はほとんど変わりません。定常は「トルクと粘性が釣り合う点」で決まり、慣性は釣り合いに入らないからです。慣性は釣り合うまでの速さだけを変えます。

| 質量 | yaw_gain | motor_tau | 63 % 時刻 (u = 0.5) | 定常 gz |
| --- | --- | --- | --- | --- |
| 0.25 kg | 17.956 | 0.0704 | 0.060 s | 8.998 |
| 0.5 kg | 17.933 | 0.1198 | 0.110 s | 8.988 |

13 章の式（`motor.py`）で予想した τ は 0.0673 → 0.1179 で、測った値と近いです。

**2. 静止中の gz の平均でバイアスを推定**
答え: 30 秒の静止で平均 0.020018（真値 0.02）、標準偏差 0.005025。平均の誤差は `σ/√N` で減るので、1σ で 0.001 に収めるには `(0.005/0.001)² = 25` サンプル、つまり 0.25 秒あれば足ります。区間ごとの平均の誤差 (rms) は 0.25 s で 0.00098、1 s で 0.00043、10 s で 0.00019 でした。
つまずき: `sysid.identify` は最初の 1 秒の静止のうち後半 50 行だけを使います。このログでは推定 0.0193 で、0.0007 外れました。

**3. sim-to-sim（MuJoCo のログで numpy の sim を同定して重ねる）**
答え: 定常値と立ち上がりはよく合います。同定値は motor_gain 44.89、tau 0.0704、deadband ≈ 0（1e-5）、bias 0.0193。同じ指令で numpy の sim を回すと全体の RMSE は 0.0177 rad/s です。定常は ±0.5 で 8.998 / 8.998、±0.35 で 6.305 / 6.304、63 % 時刻はどちらも 0.060 s。
合わないところ: ±0.2 の段で MuJoCo がほとんど回りません（定常 0.047 と −0.007）。xml のトルクの式にデッドバンドは無いはずですが、原因は調べていません【未確認】。

## 09 章 安全

**1. ウォッチドッグを PC 側だけに置くと**
答え: PC がフリーズした、USB が抜けた、PC のプログラムが落ちた、のときに役に立ちません。止める命令を送る側が止まっているからです。だからスケッチ側にも置きます（200 ms。12 章 演習 2 で確かめた）。

**2. 1 step 0.05、step 20 ms で 0 → 0.5**
答え: `0.5 / 0.05 = 10 step`、`10 × 20 ms = 0.2 秒`。

**3. sim にも変化率の制限を入れるべきか**
答え: 入れるべきです。実機だけに入っていると、実機のほうが遅れが大きく見え、それ自体が reality gap になります。sim と実機で同じ関数を通すのがいちばん確実です。

## 10 章 次の一歩

**1. エンコーダーで何が測れるようになるか**
答え: 車輪ごとの速さと、`v = r(ωR + ωL)/2` を積分した走った距離・位置。ただし車輪が滑ると、車輪は回っても車体は進まないので、位置はずれます。

**2. 強化学習の方策を試す前に厳しくするゲート**
答え: duty の上限と変化率の制限。方策は学習で見なかった状態で極端な指令や急な切り替えを出すことがあるからです。ウォッチドッグは方策によらずそのまま残します。

**3. ROS 2 のメッセージにするとき単位と座標の約束をどこに書くか**
答え: メッセージの定義ファイル（`.msg`）のフィールドのそばのコメント。いまの `src/physlearn/api.py` の `Command` / `Obs` と同じやり方です。ROS 2 の慣習（REP 103: SI 単位、x 前・y 左・z 上）に合わせると、ほかの部品とつなぎやすくなります。

## 11 章 IMU の実験

代役 (`imu.stand_in`、真のバイアス 0.006 rad/s) で解きました。実機では確かめていません。

**1. 前半の平均を後半から引く**
答え（90 秒のログ）: 前半の平均 0.00567。それを後半 45 秒から引くと、後半の積分は +0.475 度ずれます。後半自身の平均を引くと +0.005 度、何も引かないと +15.1 度。実験 2（同じログの平均を引く）は −0.005 度でほぼ 0 です。別の区間で測ったバイアスを使うと、平均の誤差（ここでは約 0.0003 rad/s）× 時間ぶん残ります。

**2. 10 秒と 90 秒の Allan 偏差の τ の数**
答え: 10 秒は τ = 0.01・0.1・1 s の 3 つ、90 秒は 10 s まで 4 つ。
`imu.allan` はクラスタが 9 個未満の τ を出さないので、τ = 10 s には `10 × 9 = 90 秒` 以上（サンプル 9000 個以上）が要ります。
出力: 90 秒で τ = 1 s が 0.00191、τ = 10 s が 0.00073 rad/s。

**3. 90 度と 360 度で尺度はどちらが 1 に近いか**
答え: 360 度。手で合わせる角度の誤差（例えば ±3 度）は回す角度によらずほぼ同じなので、尺度の誤差は `3/90 = 3.3 %` 対 `3/360 = 0.8 %` になります。積分のドリフトは回す時間で決まり、角度では増えません。実機では未確認。

## 13 章 モーターの物理

`motor.py` を呼んで計算しました（モーター定数は仮の値）。

**1. 減速比 n を 2 倍**
答え: b = 0 なら K は 1/2 倍、τ は 1/4 倍。`first_order(replace(m, b=0, n=...), j_eff)` で n = 1 は (K, τ) = (20.0, 0.04487)、n = 2 は (10.0, 0.01122)。
参考: xml に合わせた b のままでは n = 1 が (30.0, 0.0673)、n = 2 が (10.91, 0.01224) で、比はきれいになりません。

**2. 荷物 0.1 kg を前端 (x = +0.06) に**
答え: 中心に載せたときより `m·x² = 0.1 × 0.06² = 3.6e-4 kg·m²` だけ多く増えます。荷物を点とみなすと、中心で +0、前端で +3.6e-4。章の表のように荷物を箱の形とみなすと、中心で +1.875e-4、前端で +5.475e-4（元の I_yaw は 5.83e-4）。τ は荷物なし 0.0673 s、中心 0.0876 s、前端 0.1264 s。
つまずき: x = +0.06 は車体の箱のちょうど端です。点とみなすか箱とみなすかで答えが変わります。

**3. 電池の内部抵抗を足す（omc）**
答え: `DCMotorPivot.mo` には内部抵抗のパラメーター `Rbat`（巻線と直列）を用意しました（S031）。`simulate(DCMotorPivot, stopTime = 0.5, numberOfIntervals = 5000, simflags="-override Rbat=0.5")` で走らせると、t = 0.5 s のヨー角速度は 8.9657（内部抵抗なしは 8.9946）、t = 0.0898 s で 5.6900（定常 9.0 の 0.632 倍）でした。`motor.first_order` でも K = 30 → 30、τ = 0.0673 → 0.0897 s です。
つまり、粘性 b = 0 のこのモデルでは、内部抵抗は K を変えず（無負荷では電流が流れないので電圧が落ちない）、τ だけを `(R + Rbat)/R` 倍（R = 1.5 Ω なので 4/3 倍）に延ばします。K が下がるのは、粘性や負荷で定常にも電流が流れるときです。
つまずき: S031 より前の `mujoco_model()` は粘性 b を負（−8.3e-4）に置いていたので、同じことをすると K が 40 に上がりました（t = 0.5 s で 11.707）。
