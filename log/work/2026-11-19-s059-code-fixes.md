## 決めたこと

- `--axes -y,x,z` は、`link.main` が argparse に渡す前に `--axes` の直後の値（`--` で始まらないもの）を `--axes=値` にする（`link.axes_with_equals`）。argparse の設定（`prefix_chars` など）を変えるより小さく、`--axes=-y,x,z` はそのまま通る。
- 誤った入力は `p.error`（終了コード 2）に揃えた。`parse_axes` は `ValueError` のまま（`hwcheck.solve`・`fakexiao` が使う）で、メッセージだけ具体的にし、`link.main` が `--axes:` を付けて `p.error` にする。
- 安全ゲートの通知は `sim_log` の中、標準エラーに最初の 1 回だけ。標準出力と CSV は変えない。
- `docs_check` の厳しくする変更は、整数の厳密比較だけ既定で入れ（全対象の章で件数が前後同じ）、あとは `--strict`（既定は無効）に入れた。

## 章の担当への申し送り

- `--axes` は **どちらの書き方も通る**（`--axes -y,x,z`・`--axes=-y,x,z`、`link` で）。`hwcheck axes` の表示は `--axes=-y,x,z`。`fakexiao --axes` は今も `=` つき。
- エラーの文面が変わった所（正しい入力の出力は変えていない）:
  - ポートが開けない: `SerialException` のトレースバック → `error: ポート … が開けない（原文）。…`（`link`・`hwcheck`）。
  - `--axes a,b,c` など: `ValueError: substring not found` → `error: --axes: axes 'a,b,c' は読めない。…`。
  - `--dt 0` / `--seconds 0`: `--dt は 0〜1 秒、--seconds は 0〜… 秒` → `--dt は 0〜1 秒（今 0.0）` または `--seconds は 0〜… 秒（今 …）`。
  - 安全ゲートが作動した `sim-log`・`link id`: 無言 → 標準エラーに 1 行（標準出力・CSV は同じ）。
  - `hwcheck stream` のサンプル無し: 末尾に `（MCU の報告: # ERR …）` が付くことがある。
  - `link jog --left 0.3`: 最後の文だけ変わった。数値の行は同じ。
- `docs_check`: 既定の判定は、全対象の章で前後同じ（一致 27・差 1・飛ばした 6。差 1 は README.md:34 の `loop-demo` の期待が古いもの）。整数の期待が厳密になったので、小数に化けた件数・回数の行は今後 差 になる。
