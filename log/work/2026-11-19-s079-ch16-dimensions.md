## 決めたこと

- **寸法表**: 調査 `doc/research/2026-11-19-dimensions.md` の「寸法表に写せる行」19 行を写した（メーカーの文書は `datasheet`、販売店の値は `assumed`（参考値）。原文の該当箇所は `note` に）。うち 2 行（AE-DRV8835-S の質量、電池ボックスの質量）は調査でも【未確認】。XIAO の外形は 21 x 17.8 → 20.955 x 17.78（出典を KiCad の基板に）。AE-DRV8835-S の `board_xy` は 10 x 15、取付穴は「描いていない」まで（9.5）。
- **車体の行（ミニへの切り替え）**: 「Cytron Robo Base 2WD」の行は**消さずに**「2WD は売り切れ。使わない」と注記した。理由: 試験 `test_measured_beats_other_sources` が、この行の文字列（`Cytron Robo Base 2WD,wheel_radius,【未確認】,mm,,,,,`）を置換して使い、`cad.WHEEL_PARTS` もこの名前を読む。名前を変えると試験が落ち、コードも直す必要がある（コードは触らない）。代わりに「Cytron Robo Base Mini 2WD」の行を足した（構成、plate_xy、wheel_radius、track、axle_to_caster_x、mass。構成以外は全部【未確認】。構成は検索の要約で、商品ページの直読ではないと書いた）。`dimension()` はミニの行を読まないので、sim の値は動かない。ミニを測った後、`WHEEL_PARTS` にミニの名前を足すのは**統括に回す**（下）。
- **numpy の行**: `Params` の既定値は S041 で MJCF と同じ 30・100 mm になった。この行は `cad.dimension()` も試験も読まない（試験は MJCF の行を読む）ので、値の欄を 16・80 → 30・100 に直し、「読まれない。試験が `Params` と MJCF の行の一致を固定」と note に書いた。「sim の今の値 (MJCF)」と「筐体の想定」の行は触っていない。
- **板の外形に `TBD_`（S053 の指摘 7）**: `plate_w`・`plate_d` を `TBD_plate_w`・`TBD_plate_d` にした（上板が未測定の仮の値）。`plate_t` は材料で決める設計値なので付けていない。取付穴の `TBD_robo_hole_*` は名前も値（100 x 60 x 3.2）も変えず、コメントに「2WD を想定した値。車体はミニに変わった。実物を測ってから」。名前に `robo` が残るが、ミニも Robo Base なので変えなかった。
- **窓は貫通のまま**。窓を印（浅い溝や外形線）にすると形が変わり、XIAO をどう固定するかが未定のまま設計を先取りする。README と 16 章に「今の板は SolidCraft の流れを通す試し。XIAO の固定は未定。板が要るかはミニの実物を見てから」と書いた。
