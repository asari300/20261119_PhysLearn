## 決めたこと

### 問題 34

- 4 規則（`ghp_` 系・`sk-`・`AKIA`・`xox`）の頭の `\b` を外す。まず規則ごとに、掛からない例を走らせて確かめた（下の表）。`github_pat_` は元から `\b` が無い。
- `AKIA[0-9A-Z]{16}\b` の末尾の `\b` は残す。`AKIA` の後に大文字・数字が 17 字以上続くものは、AWS のアクセスキー（20 字）ではなく、長い別の文字列なので。試験にも「17 字続くものは伏せない」を 1 行入れた。
- `sk-` は語の中（`task-…`、`disk-…` の後ろに 20 字以上の英数字・`-`・`_`）でも伏せるようになる。漏らすより安全な側の誤りで、公開の記録では 0 行だった（下）。将来、そういう語で余分に伏せ字になることはありうる。
- `leftovers`（`--check`）は `REDACTIONS` を使い回しているので、検査側も同じ直しで効く（表の「leftovers」の列）。

### 問題 38

- `control.run` に `rows: list | None = None` を足した。渡されたらそこに行を足す（`sim_log` と同じ書き方）。返り値は変えない（返る `rows` は渡した物と同じ）。
- `run_loop` も `rows` を受けて `run` に渡す。これまで `rows += r` で足していたのをやめた（同じ list が返るので足すと 2 重になる）。
- `main` の `run` は `rows = []` を作り、`try/finally` で `--out` があって `rows` が空でなければ書く（`id` の所と同じ形）。
- `control.run` のほかの呼び出し元を `grep` で確かめた: `loop_demo`（`physlearn/__init__.py:58` の `run`）、`randomize.evaluate`、`mismatch`、`plot.figures`、`tests/test_control.py`、`tests/test_real_loop.py`。どれも `rows` を渡さないので、動きは変わらない（`rows` を渡さなければ空の list を新しく作る。前と同じ）。
- `run_loop` の docstring を、直した後の事実に合わせた（通信の例外は上がる。`rows` を渡せば、その回までの行が残る）。

#### 停止と書く順（読んで確かめた）

- `SerialPlant.step` と `reset` は、`except BaseException: self.stop(); raise` で、**例外を上げる前に停止 `S` を送る**。`link run` の途中の通信の例外（USB が抜けた、タイムアウト）は、`step` か `reset` の中の `_next` / `_send` から出るので、この経路を通る。つまり、**停止が先、`finally` の書くのが後**。
- 例外が `step` の外から出る場合（制御器 `ctrl` の中のバグなど）は、`step` の停止を通らない。`finally` の書くのが先で、`with` の `close`（停止）が後になる。遅れるのは `write_csv` の時間だけ。400 行の書き込みで 5.7 ms（この PC）。実機のウォッチドッグ（200 ms）より 1 桁以上短い。
- これを「書くのを `with` の外に出す」形にするには、`with` の本体全体（jog・still・id・run の 4 つ）を字下げし直す必要があり、差分が大きい。5.7 ms の遅れで、停止そのものの経路（`step` の `except` と `with` の `close`）は変えていないので、`id` と同じ位置（`with` の中の `finally`）にした。**統括が「それでも外に出す」と決めるなら、別の直しにする**。
- 試験には、`finally` で `write_csv` が呼ばれた瞬間の偽の XIAO の duty を記録し、`(0.0, 0.0)`（停止が先）であることを見る行を入れた。
